## 라운드 1. MLP 변형 비중 (`noid` 몫)

### 1-1. 가설과 그 근거

배포값은 `MLP_VARIANT_WEIGHT = {emb4: 0.625, noid: 0.375}`인데, `train.py`가
`wm = vw[vname] / tot / nseed`로 멤버 단위로 펼친다:

```
emb4  0.625 / 5 = 0.125     noid  0.375 / 3 = 0.125
```

**8멤버 균등 평균이다.** 변형 간 차등이 전혀 없다. 이 값은 누가 고른 것이 아니라
멤버 수의 부산물이므로 최적일 이유가 없다.

가설은 §7.24의 이 문장에서 나왔다:

> `noid`는 핸디캡 멤버가 아니라 **더 센** 멤버였다.

더 센 멤버가 3/8만 갖고 있으니 **올려야 한다**고 봤다. §7.27이 비율 변경을 기각했지만
그것은 홀드아웃 게이트였고, `reports/10` §5-3에서 그 게이트가 α 축에서 **부호까지 틀린 것**이
증명됐다. α와 같은 성질의 축(예측기 간 상대 신뢰도)이라 사전확률이 높다고 판단했다.

### 1-2. 방법 — config 로는 못 바꾼다

`train.py:380`이 이렇게 되어 있다:

```python

raw_ref, z_mlp_ref = load_members(MODEL_DIR, old, X_ref, art)
return _finish(..., mlp_wts, ...)
```

**`--artifacts-only`는 `config.MLP_VARIANT_WEIGHT`를 보지 않고 저장된 아티팩트를 읽는다.**
config만 바꾸면 조용히 아무 일도 일어나지 않는다.

대신 `artifacts.joblib`의 `mlp_weights`를 직접 패치했다. 순수한 선형 가중 벡터이고
세 곳이 같은 값을 읽으므로 일관된다:

| 읽는 곳 | 효과 |
| --- | --- |
| `load_members(MODEL_DIR, old, ...)` | `z_mlp_ref`가 새 가중으로 계산된다 |
| `raw_ref = (1−α)·lgbm + α·z_mlp` | `delta`가 그 위에서 재해결된다 |
| `_finish(..., mlp_wts, ...)` → `predict.py` | 같은 가중이 zip에 저장된다 |

**침묵 실패 방어선 4개**를 넣었다.

1. 패치 전 배포 가중이 8멤버 균등인지 — 기전 이해 자체의 검증
2. 패치 전 가중 합이 1인지
3. 패치 후 새 가중 합이 1인지 + 멤버별 before→after 출력
4. 학습 후 저장된 가중이 다시 균등이 아닌지 — 패치가 덮이지 않았는지

전부 통과했다. 실행 로그가 `0.125000 -> 0.100000` 형태로 8멤버를 모두 찍었고,

### 2-2. 축의 근거 — Brier 항등식

`y ∈ {0,1}`이라 `y² = y`이고, Brier는 근사 없이 분해된다:

```
BS = Var(p) − 2·Cov(p,y) + (p̄ − r)² + r(1−r)
```

`p' = P0 + c·(p − P0)`로 아핀 변환하면 `Var → c²Var`, `Cov → c·Cov`이므로

```
목적함수 = 2c·Cov − c²·Var        →   c* = Cov(p,y)/Var(p)
이득     = Var·(c* − 1)²
```

**c에 대해 정확히 2차다.** α 축은 `σ'(z) = p(1−p)`가 좁은 구간에서 일정하다는 근사에
기댔지만 여기는 근사가 없다.

이 형태는 원우가 §7.85에서 Murphy 분해를 버리고 채택한 것과 같다. Murphy는 이 문제에서
식별되지 않는다 — 분위 구간 REL의 편향이 `K/n·E[p(1−p)]`로 신호의 38배이고,
구간 수를 바꾸면 REL:RES 비율이 8:92에서 81:19까지 돌아다닌다.

### 2-3. 구현 — 로짓이 아니라 확률 공간

원우 §7.19는 **로짓 공간**(`z' = c·z`)으로 재서 fold 간 방향 불일치로 기각했다
(fold2023은 `c<0.90`, fold2024는 `c=1.05`). 확률 공간이 세 가지로 낫다.

| | 로짓 스케일 | 확률 스케일 |
| --- | --- | --- |
| 곡선 | 근사적 2차 | **정확히 2차** |
| 평균 | 바뀜 → `delta` 재해결 | P0 기준으로만 이동 |
| 손대는 파일 | `train.py` + `predict.py` | **`predict.py` 3줄** |

```python
PROB_CENTER = 0.4801        # 동결 스칼라
PROB_SCALE = 1.05
p = PROB_CENTER + PROB_SCALE * (p - PROB_CENTER)
```

`PROB_CENTER`와 `c`는 **동결 스칼라 리터럴**이다. 배치 평균을 쓰면 각 행이 다른 행에
의존해 **행 독립 예측 원칙 위반**이 된다 — 쓰지 않는다.

원우 `src/predict.py`는 읽기만 하고, `submit/`에 패치본을 두고 `COPY_FILES`에서
`predict.py`를 빼 복사 단계가 덮지 않게 했다. 리키지 정적 검사는 패치본을 직접 돌렸다.

**패치 검산** — 빌드 산출물의 `std`가 정확히 `c`배다.

| zip | `std(p)` | base 대비 |
| --- | ---: | ---: |
| `p_base` | 0.050676 | 1.0000 |
| `p_c105` | 0.053210 | 1.0500 |
| `p_c115` | 0.058278 | **1.1500** |
| `p_c130` | 0.065879 | **1.3000** |

### 2-4. `c` 를 고른 과정 — 두 추정이 갈렸고, 실측이 판정했다

**추정 A (원우 꼬리 수치).** `note_bs_decomp_lowfk.md`의 fold2024 십분위:

```
최하 빈  f_k=.4156  ō_k=.4072       최상 빈  f_k=.5641  ō_k=.5782
양 꼬리 모두 f_k 가 ō_k 보다 안쪽 (under-sharp) — "전역 온도 c>1 의 자리"
역산 (중심 ȳ_2024=.4861):  최하 1.119 · 최상 1.181   →  c ≈ 1.15
```

**추정 B (분산식 역산).** `p_base`의 LB 점수와 `std(p)`로:

```
c* = [BSS·r(1−r)/1e5 + Var(p) + (p̄−r)²] / (2·Var(p))
```

| r 가정 | 0.470 | 0.475 | 0.480 | 0.486 |
| --- | ---: | ---: | ---: | ---: |
| `c*` | 1.099 | 1.066 | 1.044 | 1.030 |
| c=1.15 이득 | +7.3 | −2.7 | −9.6 | −14.1 |
| c=1.30 이득 | −31.8 | −51.7 | −65.6 | −74.4 |

**두 추정이 갈렸다.** A는 1.15, B는 1.03~1.10. 그래서 `c115`/`c130`을 쏘는 대신
**`c105`를 새로 빌드**했다 — B가 맞으면 챔피언 후보이고, A가 맞아도 곡선 정보는 같기 때문이다.

> LB 점수엔 측정 오차가 없고 곡선이 정확히 2차라, 서로 다른 3점이면 **간격에 무관하게**
> 꼭짓점이 정확히 나온다. 가까이 붙은 점을 써도 손해가 없다 — 이것이 `c105`를 고를 수 있었던 이유다.

**B가 맞았다.** 이유는 `init_score`다. A의 근거는 **s24 스택**의 십분위인데, 그 뒤 들어온
`init_score`가 바로 레벨을 학습 전에 제거하는 조작이라 캘리브레이션이 개선됐고
under-sharp 여지가 줄었다. **B는 현재 스택의 실제 LB 점수를 썼다.**

### 2-5. 곡선 확정 — 2점으로 끝났다

곡률은 이론값으로 정해진다: `d²score/dc² = −2[Var(p) + (p̄₀−P0)²]·1e5 / r(1−r)`.
따라서 **2점이면 꼭짓점이 나온다.**

```
score(c) = −1064.0·c² + 2242.9·c − 94.8

꼭짓점  c* = 1.0540      최대 1087.2508  (+3.108)
```

| c | 예측 | base 대비 |
| ---: | ---: | ---: |
| 1.00 | 1084.143 | 0 |
| **1.05 (실측)** | **1087.233** | **+3.090** |
| 1.054 | 1087.251 | +3.108 |
| 1.10 | 1085.004 | +0.861 |
| 1.15 | 1077.454 | −6.689 |
| 1.30 | 1022.887 | −61.256 |

**`r` 가정(0.470~0.486)에 거의 무관하다** — 곡률을 `Var(p)`가 지배해 `c*`가
1.0540~1.0541로 고정이다. 레벨 상수를 몰라도 이 축은 결정된다.

**남은 여지 +0.018. 온도 축 종결.** `c115`(−6.7 예상)와 `c130`(−61 예상)은 쏘지 않았다 —
곡선이 확정돼 정보 가치도 없다. **슬롯 2개를 아꼈다.**

### 2-6. 이론 상한과의 대조

단조 변환이라 **RES는 못 건드리고 REL만 줄인다** (순서 불변 → 빈 구성 불변 → `ō_k` 불변).
따라서 이득의 상한은 현재 REL이다.

```
실측 이득           1e5·Var·(c*−1)²/u = 3.008      (+3.090 과 일치)
원우 10빈 REL       0.000040 → BSS 16.0            (10빈은 하한 추정, 상한 아님)
```

10빈 REL이 16점인데 전역 스케일로 회수한 건 3.1점이다. 차이는 **전역 스케일로 못 고치는
빈별 잔여 miscalibration**이다. 그걸 고치려면 행별 보정이 필요하고, 그건 RES 채널이다.

### 3-4. 부족분의 정체 — 두 조작이 같은 자원을 쓴다

부족분은 전부 **`c`의 기여가 줄어든 것**으로 설명된다.

```
c = 1.05 의 기여
  base (noid .375) 위에서   +3.0902
  noid 0           위에서   +2.1381      (−0.9521)
```

항등식에서 `c = 1.05`의 이득은 `K[0.1·Cov − 0.1025·Var]`이다. `noid`를 빼는 것도 결국
예측을 퍼뜨리는 조작이라, **이미 퍼진 스택에는 `c`가 고칠 under-sharpness가 덜 남아 있다.**

두 축이 서로 다른 노브처럼 보였지만 **같은 자원(현재 샤프니스와 최적 샤프니스의 간격)을
소비한다.** 겹치지 않은 것은 *구현 지점*이지 *효과*가 아니었다. — 이것이 라운드 4의
축 선정 기준이 된다. **다른 항을 건드리는 축이라야 진짜로 가법이다.**

### 3-5. `c` 축은 새 스택에서도 소진됐다

`noid = 0` 스택의 `c*`를 역산한다 (`u ≡ K·Var`):

```
ΔScore(c) = u[2(c−1)c* − (c²−1)]        c = 1.05 의 잔여 손실 = u(c* − 1.05)²
u(0.1·c* − 0.1025) = 2.1381
```

`Var`를 직접 못 재므로 `u`를 넓게 흔들어 본다.

| `u = K·Var` | 대응 std | `c*` | 1.05 의 잔여 손실 |
| ---: | ---: | ---: | ---: |
| 700 | 0.0418 | 1.0555 | 0.02 |
| 900 | 0.0474 | 1.0488 | 0.00 |
| 1065 | 0.0515 | 1.0451 | 0.03 |
| 1300 | 0.0570 | 1.0414 | 0.10 |
| 1600 | 0.0632 | 1.0384 | 0.22 |

**`Var` 가정에 거의 무관하게 잔여가 0.22점 미만이다.** `c` 축은 끝났다.

**2026-08-24 확정.** §4-2 측정이 `std = 0.052094`(245,789행 더미)를 줬다.
`u = K·Var = 1087.4`로 위 표의 1065 행 바로 옆이다.

```
c* = 1.0447        c = 1.05 의 잔여 손실 = 0.031점
```

스윕이 아니라 **실측으로 확정됐다.** 결론은 그대로다.

(이 `c*`는 `noid = 0` 스택에서 역산한 값이다. 챔피언이 `x12`로 바뀌었으니 엄밀히는
`noid = .125` 스택에서 다시 역산해야 하지만, §3-6이 보인 대로 두 스택의 차이가
0.07점 규모라 `c*`는 소수 셋째 자리에서나 움직인다. 잔여는 여전히 0.03점 수준이다.)

### 3-6. `p_x12` 예측이 틀렸다 — 꼭짓점은 `c`에 고정돼 있지 않다

원래 이 절은 `p_x12`를 **쏘지 않기로** 하며 이렇게 적었다.

> `noid` 꼭짓점이 `−0.00238`이라 `c = 1.05`에서도 0 쪽이 낫다.
> §3-4의 상호작용을 반영하면 실제 예상은 **약 +4.0**으로 챔피언(+4.2295) 아래다.

08-23 마지막 슬롯으로 실제 쏴 봤고 **`1088.4433490873` (+4.3002)** 이 나왔다.
`x00`보다 **+0.0706 위**이고, 예상보다 **+0.3** 위다. 새 챔피언이다.

**틀린 지점은 하나다 — `noid` 꼭짓점이 `c`에 대해 고정이라고 봤다.** 아니다.
항등식에서 바로 나온다:

```
f_c(x) = −K[c²V(x) − 2c·C(x)]
       = c·f_1(x) − K·c(c−1)·V(x) + const        (x = noid 몫)
```

`c = 1.05`에서 `K·c(c−1) = 21,036.75`이고, **`V(x)`는 `noid` 몫이 커지면 감소한다**
(20,000행 더미 스케일 전 std: `x=0` 0.051550 → `x=.125` 0.051247).
따라서 `−K·c(c−1)·V(x)` 항이 `x`를 **위로 민다.** `c`가 오르면 `noid` 최적도 오른다.

이것은 §3-4에서 *"두 조작이 같은 자원을 쓴다"*고 쓴 것과 **같은 기전**이다. 기전은
맞게 봤는데 꼭짓점까지 따라가지 않았다. 가법성이 81.6%로 깎인다는 것을 알았으면
꼭짓점이 움직인다는 것도 따라 나왔어야 했다.

**`c = 1.05`에서의 꼭짓점.** 두 점(`x=0` +4.2295, `x=.125` +4.3002)과 곡률 `A`로:

| `A` | 꼭짓점 `x_v` | `x = .125`의 잔여 |
| ---: | ---: | ---: |
| −10 | 0.0907 | 0.012 |
| −15 | 0.0813 | 0.029 |
| −20 | 0.0766 | 0.047 |

**꼭짓점 0.077~0.091, 잔여 0.01~0.05점.** 곡률 가정에 무관하게 작다.
결론(*"슬롯 쓸 값이 아니다"*)은 유지되지만, **근거가 달라졌다** — 경계값에 닿아서가
아니라 이미 꼭짓점 옆에 서 있어서다.

**교훈.** 2축을 다룰 때 한 축의 꼭짓점을 다른 축의 값에 대해 상수로 두면 안 된다.
`c` 축을 열었으면 `noid` 꼭짓점을 **다시 재야** 했다. 0.07점짜리 실수였지만 같은 실수를
`Δ` 축에서 하면 규모가 다르다 — 다행히 `Δ`는 `Var`·`Cov`를 안 건드려 **구조적으로**
직교한다(§4-5). 그것이 이 축을 고른 이유이기도 하다.

## 라운드 4. 레벨 축 — 아무도 안 건드린 항 (2026-08-23)

### 4-1. 항 감사 — 우리가 판 곳은 한쪽뿐이었다

```
BS = Var(p) − 2·Cov(p,y) + (p̄ − r)² + r(1−r)
     └─────────┬────────┘   └───┬───┘   └──┬──┘
          refinement            레벨     상수(불가침)
```

| 항 | 우리가 판 축 | 이득 |
| --- | --- | ---: |
| `Var` · `Cov` | `MLP_ALPHA`(구 스택) · `noid` 몫 · 확률공간 `c` | +8.48 · +4.23 |
| **`(p̄ − r)²`** | **없음** | **0** |

`reports/10`부터 지금까지 **refinement 항만 파고 있었다.** 레벨 항은 한 번도 LB로 재본 적이
없고, 이는 우리뿐 아니라 **원우 브랜치 전체(§7.116까지)도 마찬가지다.**

### 4-2. 왜 비어 있었나 — 원우가 스스로 규모를 적어 뒀다

`TARGET_PRIOR_2025 = 0.475`는 MODEL.md §3-3에서 **학습 데이터 논증**으로 정해졌다
(R4 방법론 → `0.4897 − 0.0120 = 0.4778`, `F`(12%) ≈ 0.452 혼합 → 0.475). 그리고 이렇게
방어된다:

> **손실 민감도** (`BSS 손실 ≈ −400,700 × (선택 − 진값)²`)
>
> | 선택 ＼ 진값 | .465 | .470 | .475 | .480 | .486 | .495 | 최악 |
> | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
> | 0.486 (드리프트 무시) | −177 | −103 | −48 | −14 | 0 | −32 | **−177** |
> | 0.470 (R4 전체기준) | −10 | 0 | −10 | −40 | −103 | −250 | **−250** |
> | **0.475 (채택)** | −40 | −10 | 0 | −10 | −44 | −160 | **−44** |
>
> 0.475는 진값이 .465~.486 어디에 있어도 −44점 이내다.

이것은 **미니맥스 선택이지 측정이 아니다.** 원우 본인이 *"최대 44점 손실을 감수한다"*고
명시적으로 적어 둔 것이다. 우리가 지금까지 refinement 항에서 딴 총액이 +12.7인데,
**이 한 항의 미결 규모가 0~44점이다.**

`K ≡ 1e5 / (r(1−r)) ≈ 400,700`은 우리가 라운드 2에서 항등식으로 유도한 계수와 같은 값이다.
두 경로가 독립적으로 일치한다.

### 4-3. 구현 어긋남 — δ는 2024 라벨에서 풀고 2025 라벨에 적용된다

`train.py:565`:

```python
delta = solve_delta(base + raw_ref, TARGET_PRIOR_2025)   # z_ref = df[df.season == 2024]
```

`solve_delta`는 **`season = 2024` 라벨이 붙은 2024 행**에서 `mean(sigmoid(z + d)) = 0.475`인
`d`를 푼다. 그 스칼라를 동결해 **`season = 2025` 라벨** 행에 적용하면, `season`이 피처로
들어가므로 로짓이 달라지고 **평균이 목표에서 벗어난다.**

이건 새로 발견한 종류가 아니다. 원우가 MODEL.md §596에서 같은 버그를 잡은 적이 있다:

> 같은 2024 행에 `season` 라벨만 바꿔 예측하면 평균이 **0.4750 → 0.4731**로 어긋난다.
> 즉 모델이 지시받은 0.475를 실제로는 못 맞추고 0.473을 낸다. 레벨 손실 ~16 BSS 규모.
> … 교훈: prior shift의 참조 분포는 **행이 아니라 피처 분포**를 기준으로 골라야 한다.

그리고 `build_submit.make_dummy_test`의 독스트링이 **이 검사를 하라고 스스로 적어 뒀다**:

> 2024 시즌 행을 쓴다. 2025 test의 피처 분포에 가장 가까우므로 추론 **시간**뿐 아니라
> 예측 **평균**도 의미 있는 검사가 된다 (logit_delta를 2024 행 기준으로 풀었으니
> 평균이 `TARGET_PRIOR_2025` 근처여야 한다).

**현 s29 스택에서 이 검사가 실제로 통과하는지 아무도 확인하지 않았다.** 노트북 §4-2가
그것을 직접 잰다.

### 4-4. `0.4801`의 출처 — 정정

`PROB_CENTER = 0.4801`은 원래 이렇게 주석돼 있었다: *"245,789행 더미 예측 평균"*.
정확히는 다음 두 가지를 함께 적어야 한다.

1. **구 스택 값이다.** `reports/10` §2-2의 α 라운드 8제출(베이스 1076.03)에서 나온 수치이고,
   그 뒤 `init_score`(§7.111) · F전문가(§7.101) · soft label(§7.70) · 달력드랍(§7.78)이
   들어온 **현 s29 스택의 값이 아니다.**
2. **실제 test 평균이 아니라 `make_dummy_test` 값이다.** 그 더미는 2024 시즌 행
   (253,507행) 중 앞 245,789행에 `season = 2025`를 붙인 것이다. 원우가 *"2025 test의 피처
   분포에 가장 가깝다"*고 지정한 대리값이며, 실제 2025 test 피처 분포와는 다르다.

현 스택의 `§6` 검증 로그에 찍힌 `mean 0.4895`도 레벨 추정에 **쓸 수 없다.** 그것은
`make_dummy_test(20000)` — 2024 시즌 **앞 20,000행**뿐이라 3~4월만 들어간다. 시즌 내부에서
3월 .5026 → 9월 .4757로 내려가므로(원우 §3) 위로 크게 편향된다. 레벨을 재려면 **전체 규모**여야
한다. 그래서 노트북에 `## 4-2` 셀을 새로 넣었다.

이 정정은 계획을 흔들지 않는다. `Δ`가 확정하는 양 `b = p̄ − r`은 **`p̄`가 얼마인지 몰라도
LB 한 점에서 그대로 나온다.** `p̄`는 (i) 스텝을 고르고 (ii) `b`를 `r`로 번역할 때만 쓴다.

**2026-08-24 측정 결과 — 우려는 무해하게 해소됐다.**

| | 값 |
| --- | ---: |
| 구 스택(α 라운드) 245,789행 평균 | 0.4801 |
| **현 s29 스택 245,789행 평균** | **0.480125** |
| 차이 | **+0.000025** |

`init_score` · F전문가 · soft label · 달력드랍이 전부 들어왔는데도 **레벨은 두 세대에 걸쳐
사실상 동일하다.** `solve_delta`가 매번 참조 시즌 평균을 0.475로 다시 고정하므로, 스택이
바뀌어도 `season` 라벨 교체로 생기는 어긋남의 크기가 유지되는 것으로 보인다.

정정 자체는 유지한다 — 우연히 같았을 뿐, 확인하지 않고 쓸 근거는 없었다.

### 4-5. 계측기 — 확률공간 레벨 이동

`p' = p + Δ`는 `Var`도 `Cov`도 바꾸지 않고 `p̄`만 옮긴다. 항등식에 그대로 넣으면

```
BS' − BS = 2Δ·b + Δ²          (b ≡ p̄ − r)
```

세 가지가 좋다.

**1. 곡률이 이론적으로 알려져 있다.** `Δ²`의 계수가 **정확히 1**이다 — 적합할 게 없다.
`c` 축은 2점이 필요했지만 여기는 **LB 한 점이면 `b`가 확정된다**:

```
b = − (ΔScore / K + Δ²) / (2Δ)
```

**2. `c` 축과 정확히 직교한다.** 최종 평균은 `P0 + c(p̄ − P0) + Δ`이므로 `Δ`를 목표에 맞춰
잡으면 `P0`·`c`가 무엇이든 같은 레벨이 된다. `Var`·`Cov`는 `Δ`와 무관하다.
→ §3-4에서 겪은 상호작용이 **구조적으로 없다.** 다른 항을 건드리기 때문이다.

**부수 소득 — `c` 축 측정의 오염 여부를 확인할 수 있다.** `P0 ≠ p̄`인 채로 스케일을 걸면
평균이 `(c−1)(p̄ − P0)`만큼 딸려 움직여 레벨 항이 `c` 측정에 섞인다.

> **2026-08-24 정정.** 이 절은 원래 `p̄ − P0 = 0.005`로 잡고 **"약 −1점이 섞였을 수 있다"**고
> 썼다. 과대추정이었다. §4-2 실측이 `p̄ = 0.480125`, `P0 = 0.4801`이라
> **`p̄ − P0 = 2.5e−05`**임을 보였다. 평균 이동은 `1.25e−06`이고 레벨 항 오염은
> `b = 0.005`일 때 **−0.005점**이다.
>
> **`c105`의 +3.0902는 깨끗한 refinement 측정이었다.** `P0 = 0.4801`을 구 스택에서
> 가져온 것이 우연히 맞아떨어졌다 — 운이 좋았던 것이지 설계가 아니었다.

`Δ`가 붙으면 이 문제는 원리적으로 사라진다. 최종 평균이 `P0`·`c`와 무관해지기 때문이다.

**3. `train.py`를 안 건드린다.** `_c`와 같은 삽입 지점에 한 줄 추가다.

### 4-6. 손익 구조 — 손익분기는 정확히 중점이다

`off ≡ p̄ − 0.475`(측정된 어긋남)에 대해 `Δ = −off`를 얹으면

```
ΔScore = K[2·off·b − off²]        →  b > off/2 일 때 이득
```

즉 **진값 `r`이 `(0.475 + p̄)`의 중점보다 아래면 이긴다.** 대칭적이라 읽기 쉽다.

| 측정될 `p̄` | `off` | 손익분기 `r` | `r = 0.475`이면 | 현 레벨이 이미 최적이면 |
| ---: | ---: | ---: | ---: | ---: |
| 0.4780 | 0.0030 | 0.47650 | **+3.6** | −3.6 |
| 0.4801 | 0.0051 | 0.47755 | **+10.4** | −10.4 |
| 0.4830 | 0.0080 | 0.47900 | **+25.6** | −25.6 |
| 0.4870 | 0.0120 | 0.48100 | **+57.7** | −57.7 |

**그리고 어느 칸이 나오든 `b`가 이 한 점으로 확정된다.** 지면 내일 `Δ* = −b`를 그대로 얹어
`K·b²` 전액을 회수한다. 즉 **잃는 것은 슬롯 하나이고 얻는 것은 축 전체**다.

### 4-8. 규정 — 부록 A의 판단을 철회한다

부록 A는 *"LB로 prior를 스윕하지 않는다"*고 닫으면서 이렇게 구분했다.

> α는 두 예측기 중 무엇이 잘 일반화하는지를 고르는 **모델 선택**이고, LB가 알려주는 것은
> 라벨 통계가 아니다. prior 스윕은 LB가 **평가 데이터 라벨의 평균값**을 알려준다 → 위반.

**이 구분은 우리가 이미 네 번 제출한 `c` 축과 `Δ` 축을 가르지 못한다.**
`c* = Cov(p,y)/Var(p)`는 `y`가 들어간 **평가셋 라벨 통계** 그 자체다 —
`p`에 대한 `y`의 회귀 기울기다. LB로 `c`를 맞추는 것이 허용된다면 `Δ`도 같은 종류다.
둘 중 하나만 위반이라고 볼 근거가 부록 A에 없다. 그리고 `c`를 철회할 생각은 없다.

**실제로 규칙이 금지하는 것은 다른 것이다** — *추론 시점에* 다른 행이나 전체 분포를
참조하는 것. `P0`·`c`·`Δ`는 전부 파일에 박힌 **동결 스칼라 리터럴**이고, 각 행의 예측은
자기 피처에만 의존한다. `§6`의 셔플·청크 검사가 매 제출마다 이것을 확인한다
(임계값 `1e-6`, 실측 잔차는 BLAS 노이즈 수준).

**그리고 이번 라운드는 애초에 LB가 필요 없다.** 쓰는 값은

```
Δ = 0.475 − (측정된 2025라벨 예측평균)
    └─┬──┘   └──────────┬──────────┘
  원우가 학습          우리 모델이
  데이터만으로         자기 예측에서
  도출한 목표          낸 수치
```

**test 라벨은 한 톨도 들어가지 않는다.** §4-3의 구현 어긋남을 원우 자신의 목표값으로
되돌리는 값이다.

**남는 위험은 정직하게 적어 둔다.** LB 결과가 0.475가 아닌 지점을 가리키고 **거기에 맞춰
`Δ`를 다시 잡는다면**, 그때는 실제로 평가 라벨 평균을 박아 넣는 것이 된다.
그 선을 넘을지는 그때 팀이 판단한다 — **이번 라운드는 넘지 않는다.**

### 4-12. 결과 — `1049.6425674531`. 축이 열렸다

```
p_lv.zip   2026-08-24 00:04   LB 1049.6425674531
기준선 p_x00 = 1088.372727694   ->   ΔScore = −38.7302
```

**판정표(§4-11)의 세 번째 행이다** — `−K·off²`(−10.5)보다 훨씬 더 떨어졌다.
`b < 0`, 즉 **진값이 `p̄`보다 위**라는 뜻이다. 미리 적어둔 대로 드리프트 가정 자체가 틀렸다.

`b`를 뽑는다. `K = 1e5/(r(1−r))`가 `r`에 의존하므로 반복해서 수렴시킨다.

```
b = −(ΔScore/K + Δ²) / (2Δ)  =  −0.006875
r = p̄ − b = 0.480125 + 0.006875 = 0.487000        (K 수렴 400,271)

검산:  −K[2Δb + Δ²] = −38.7302   vs 실측 −38.7302     ← 소수 넷째 자리까지 일치
```

**항등식이 정확히 맞았다.** 곡률을 이론값 1로 놓은 것이 옳았고, 한 점으로 충분하다는
§4-5의 주장이 실측으로 확인됐다. 방향만 반대였다.

| | 값 |
| --- | ---: |
| 우리 예측 평균 `p̄` | 0.480125 |
| **평가셋 라벨 평균 `r`** | **0.487000** |

| 최적 `Δ* = −b` | **+0.006875** |
| `Δ = 0` 대비 최대 이득 `K·b²` | **+18.92** |

**우리 예측이 낮았다. 위로 밀어야 한다.**

> 인정하고 미니맥스로 방어했고, 그 표의 다른 행(0.486)이 정답에 가장 가까웠다.
> **우리가 한 일은 그의 불확실성 인정을 무시하고 한 점을 더 확신한 것이다.**

`r`을 실측한 지금, 이 축에서 시계열 외삽은 더 이상 필요 없다.

## 라운드 5. 세그먼트 분해 — 설계 (2026-08-24)

### 5-1. 전역 항등식은 소진됐다

```
BS = Var(p) − 2·Cov(p,y) + (p̄ − r)² + r(1−r)
     └────────┬────────┘   └───┬───┘   └──┬──┘
      α·noid·c → +4.30       Δ → +18.9    불가침
```

세 항을 다 건드렸고 값도 다 알아냈다 — `c* = 1.045`, `noid* ≈ 0.08`, `r = 0.487000`.
**전역에서 더 짤 것이 없다.** 다음은 같은 방법을 한 층 아래에서 반복하는 것이다.

### 5-2. 세그먼트 분해와 그 이득

```
BS = Σ_g w_g [ Var_g − 2·Cov_g + (p̄_g − r_g)² ] + Σ_g w_g·r_g(1−r_g)
```

전역 `Δ` 하나는 `Σ w_g(p̄_g − r_g)`만 0으로 만든다. **세그먼트별 편차는 남는다.**
두 세그먼트일 때 세그먼트별 `Δ_g`로 내려가면

```
이득 = K · w_1 · w_2 · (b_1 − b_2)²
```

즉 **세그먼트 간 오차의 분산**이 그대로 점수다.

| `\|b_R − b_F\|` | 이득 (`w_F = 0.1184`) |
| ---: | ---: |
| 0.005 | +1.0 |
| 0.010 | +4.2 |
| 0.020 | **+16.7** |
| 0.030 | **+37.6** |

### 5-3. `game_type`이 첫 후보인 이유

`data/train.csv` 시즌 × `game_type` 실측:

| 시즌 | F | R | F 비중 |
| --- | ---: | ---: | ---: |
| 2019 | .6892 | .5495 | 10.9% |
| 2020 | .5878 | .5269 | 9.5% |
| 2021 | .7038 | .5128 | 10.5% |
| 2022 | .7087 | .5037 | 12.3% |
| 2023 | .4729 | .5031 | 10.5% |
| **2024** | **.4593** | **.4897** | **11.8%** |

**F는 2022 → 2023에 −0.236 튄다.** 드리프트가 아니라 정의·체제 변화다
(원우 §7.49의 pre-2023 F 오염 보정이 이 자리다). R은 같은 구간에서 −0.0006이다.

원우 §3-3은 그런 계열의 2025값을 **0.452**로 외삽했다 — 하향 추세의 연장이고,
**전역에서 틀린 것과 정확히 같은 종류의 외삽이다.** 실제 F가 2024 수준(.4593)에
머물렀다면 그 자리에만 `+0.0073`의 오차가 있고, `w_F = 0.118`을 감안해도
`b_R − b_F`가 0.01~0.02 대역이면 **+4~17점**이다.

### 5-4. LB 없이 열린다

전역에서 확인된 **"드리프트 = 0"** 가설을 세그먼트에 그대로 적용한다.

```
R 목표 = 0.4897        F 목표 = 0.4593        (둘 다 2024 실측)
가중 평균 = 0.8816 × 0.4897 + 0.1184 × 0.4593 = 0.48610
```

**전역 목표 0.4861과 정확히 일치한다.** 즉 라운드 5는 라운드 4의 *분해*이지 새 가정이
아니다. 필요한 것은 더미에서 `p̄_R`·`p̄_F`를 재는 것뿐이고, **평가 라벨은 한 번도 안 읽는다.**

§4-14 규정표의 첫 줄에 해당한다.

### 5-5. 구현

`predict.py`가 이미 `test_df["game_type"]`을 쓴다 (§7.101 F전문가, `predict.py:120`).
같은 삽입 지점에서 `PROB_SHIFT`를 스칼라 대신 **행별 벡터**로 만들면 된다.

```python
PROB_CENTER = 0.4801
PROB_SCALE  = 1.05
SHIFT_R     = <측정>
SHIFT_F     = <측정>
p = PROB_CENTER + PROB_SCALE * (p - PROB_CENTER)
p = p + np.where(is_f, SHIFT_F, SHIFT_R)
```

`SHIFT_R`·`SHIFT_F`는 여전히 **동결 스칼라 리터럴**이고, 각 행은 **자기 `game_type`만**
본다. 행 독립성이 유지된다 — §6의 셔플·청크 검사가 이것을 확인한다.

## 라운드 7. 곡률 스크리너 — 슬롯 없이 축 3개를 닫았다 (2026-08-24)

### 7-1. 왜 필요했나

슬롯이 하나 남았는데 후보가 넷이었다. 넷 다 같은 상태다 — **홀드아웃으로 정해졌고
LB로 안 쟀다.** 우리가 5전 5승한 조건이다.

그런데 그 조건은 **필요조건이지 충분조건이 아니다.** `LGBM wide 몫`도 똑같이
미측정이었는데 원우 §7.131이 곡률 `0.6`을 재고 슬롯 없이 큐에서 뺐다.

### 7-2. 방법 (원우 §7.131)

레벨을 재고정한 기준에서 예측을 1차 전개하면

```
p(x) ≈ p₀ + (x−x₀)·d ,   d = dp/dx
BS(x) = BS₀ + (x−x₀)(A₁−2B₁) + (x−x₀)²·Var(d)

C ≡ K·Var(d)          이득(x*) = C·(x*−x₀)²
```

`d`를 **중심화**하는 것이 레벨 재고정이다 — `Δ`가 어차피 평균을 다시 묶으므로 평균
성분은 이 축의 이득이 아니다. `C`는 라벨이 필요 없다. 축당 더미 추론 2회, 약 3분.

### 7-3. 결과

| 축 | 배포 | `C` | `\|Δp\|` (h 이동) | ±h | ±2h | ±5h |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| MLP `noid` 몫 | 0.125 | 15.54 | 2.4e−04 | 0.039 | 0.155 | 0.971 |
| `CTX_HALF_LIFE` | 1.0 | 2.57 | 4.3e−04 | 0.161 | 0.642 | 4.016 |
| `CTX_K` | 200 | **0.00** | 3.3e−04 | 0 | 0 | 0 |
| `ASOF_STRENGTH` | 35 | **0.00** | 1.1e−06 | 0 | 0 | 0 |

> **⚠️ 출력 버그를 기록한다.** 노트북 셀이 처음에 `±h` 열에 `C`를 그대로 찍었다.
> 이득은 `C·(x*−x₀)²`이므로 `h²`을 곱해야 하는데, 축마다 `h` 단위가 달라
> 그대로 비교하면 `noid` 몫이 `CTX_HALF_LIFE`보다 6배 커 보인다 (실제로는 1/4다).
> 원우 표로 검산해 공식이 맞고 출력만 틀렸음을 확인했다:
> `17.8 × 0.10² = 0.18` · `17.8 × 0.25² = 1.11` · `17.8 × 0.875² = 13.6` — 그의 표와 일치.

### 7-4. 세 축을 닫는다

**`ASOF_STRENGTH`** — `35 → 42`로 예측이 `1.1e−06` 움직인다. 사실상 무반응이다.

**`CTX_K`** — `|Δp| = 3.3e−04`로 움직이는데 **`C = 0.00`**이다. 변화가 거의 전부
**평균 이동**이고 순서를 안 바꾼다. `Δ`가 레벨을 다시 묶으므로 **남는 것이 없다.**
이 축은 "효과가 없다"가 아니라 **"효과가 레벨 축과 완전히 겹친다"**가 정확한 표현이다.

**`noid` 몫** — `C`는 15.54로 크지만 **경계(0)까지 가도 `15.54 × 0.125² = 0.243`**이다.
우리 추정 꼭짓점(0.085)이면 **0.025**다. 원우가 곡률표에 올려놓고 LB 프로브를 안 한
이유가 이것으로 설명된다.

### 7-5. 남은 축도 상한이 낮다 — 홀드아웃이 이번엔 도움이 됐다

`CTX_HALF_LIFE`는 원우 §7.61이 **이미 스윕했다.**

```
None +0.00/+0.00 · 4.0 +1.45/+1.05 · 2.5 +2.10/+1.44
1.5 +2.77/+1.84 · 1.0 +2.76/+2.03 ← 봉우리 · 0.5 +0.09/+1.96
```

**단봉이고 봉우리가 `1.0~1.5`에 갇혀 있다.** 두 fold 모두 2.5 이상을 명확히 기각한다.
따라서 변위 상한이 0.5이고 **이득 상한 `2.57 × 0.25 = 0.64`**다.

> 홀드아웃을 5번 이겨 왔지만, **여기서는 홀드아웃이 상한을 묶는 데 쓰였다.**
> 우리가 이긴 축들은 전부 *혼합 가중*(α · noid · c · fspec)이었고 홀드아웃이 봉우리를
> 낮게 잡는 계열이었다. `CTX_HALF_LIFE`는 δ 표를 만드는 **데이터 가중** 상수라
> 계열이 다르다. 그리고 곡률이 작아서 홀드아웃이 크게 틀려도 규모가 안 나온다
> (+2를 얻으려면 꼭짓점이 1.88이어야 하는데 두 fold가 2.5를 기각한다).

### 7-6. 판정 — 슬롯을 쓰지 않는다

사전 등록한 규칙: *"꼭짓점이 ±2h 밖에 있다고 봐도 이득이 1점 미만이면 안 쓴다."*
`0.64 < 1`. **네 축 전부 닫는다.**

**스크리너가 제 값을 했다.** 7분으로 축 3개를 닫고 4번째의 상한을 0.64로 묶었다.
안 돌렸으면 감으로 하나 찍었을 것이고 3/4 확률로 0.03점짜리를 쐈을 것이다.
그리고 **원우 곡률표에 없던 세 축을 우리가 채웠다** — 팀 큐에서 영구히 빠진다.

### 7-7. 닫힌 축 (라운드 7 기준)

| 축 | 근거 |
| --- | --- |
| `CTX_K` | `C = 0.00`. 효과가 레벨 축과 완전히 겹친다 |
| `ASOF_STRENGTH` | `\|Δp\| = 1.1e−06`. 무반응 |
| MLP `noid` 몫 | 경계까지 가도 +0.243. 추정 꼭짓점에서 +0.025 |
| `CTX_HALF_LIFE` | 곡률 2.57 × 홀드아웃이 묶은 변위 0.5 → 상한 +0.64 |

## 라운드 8. δ 개별 β — 방향을 틀렸다. 그러나 축은 살아 있다 (2026-08-24)

### 8-1. 발단 — config 주석이 스스로 적어 뒀다

`ASOF_AXES` 바로 위 주석:

> β는 **고원 기하**로 골랐다 **(점수 아님)**: 밴드 허용 구간의 최대값 한 칸 아래.
> `gap_success` 고원 [0.005,0.06] → 허용 [0.01,0.04] → 0.03
> `gap_bsuccess` 고원 [0.005,0.04] → 허용 [0.01,0.025] → 0.02

`CTX_AXES`도 같다 — `β = 1.5×1.25, 1.0×1.25`에서 **`1.5:1.0` 비율은 밴드 규칙**이고
`×1.25`만 고원에서 맞춘 전역 배율이다.

**넷 다 휴리스틱으로 정해졌다.** 그리고 원우 §7.131이 LB로 최적화한 것은
**그 넷의 공통 배율 하나**뿐이다 (`β* = 0.9907`, 배포값이 이미 최적).

```
CTX_AXES  = [("hand", 1.875), ("count4", 1.25)]
ASOF_AXES = [("gap_success", 0.03), ("gap_bsuccess", 0.03)]
                            └─ 넷의 총량은 맞다.  넷 사이의 배분은 미측정 ─┘
```

### 8-2. 왜 이 자리가 남아 있나 — 세 번 본 패턴

| 축 | 배포값이 정해진 방법 | LB 결과 |
| --- | --- | ---: |
| MLP `noid` 몫 0.375 | **8멤버 균등 평균의 부산물** (아무도 고르지 않았다) | +1.85 |
| `MLP_ALPHA` 0.40 | 홀드아웃 | +8.48 |
| `FSPEC_ALPHA` 0.15 | fold 2023H2 (11,151행) | +2.04 |
| **δ 개별 β** | **고원 기하 (점수 아님)** | **?** |

전부 *"합리적 기본값"*이고 *"최적값"*이 아니다. 그리고 셋 다 움직였다.

### 8-3. 공통 배율이 최적이라는 사실이 오히려 유리하다

`β* = 0.9907`은 **"전부 같이 키우거나 줄이는 방향"의 미분이 0**이라는 뜻이다.
한 축의 β만 흔들면 그 섭동은

```
(β 하나만 이동) = (비율 방향) + (전역 스케일 방향)
                                └─ 1차 기여가 0 ─┘
```

이므로 **측정되는 것이 순수하게 비율 효과다.** 공통 배율 축과 자동으로 직교한다.

### 8-4. 절차 — 곡률 먼저, 슬롯은 그 다음

라운드 7과 같다. 축 4개에 곡률 스크리너를 돌린다 (**슬롯 0개**, 약 6분).

| 축 | 배포 | 섭동 (+20%) |
| --- | ---: | ---: |
| `hand` β | 1.875 | 2.25 |
| `count4` β | 1.25 | 1.50 |
| `gap_success` β | 0.03 | 0.036 |
| `gap_bsuccess` β | 0.03 | 0.036 |

**참고 눈금.** 원우 §7.131의 공통 배율이 `C = 83.1`이다. 개별 β는 그 일부를 나눠 갖는다.
`hand`가 δ std 0.01802로 가장 크고(`count4` 0.01314) β도 가장 크므로 `hand`가 지배할 것으로
본다. 판정은 라운드 7과 같은 규칙으로 한다 — **현실적 변위에서 1점 미만이면 안 쏜다.**

### 8-5. 미리 적어 둔 위험

- **`⛔ LB를 보고 β를 다시 고르지 않는다`가 config 주석에 있다.** 원우 규칙 2의 적용이고,
  §7.131에서 그 자신이 공통 배율을 LB로 고르며 이미 넘은 선이다. 팀 판단은 이미 정리됐다
  (대회 규칙 기준 결백, §4-8·§4-14).
- **곡률이 작을 가능성이 높다.** 공통 배율의 `C = 83.1`은 넷이 **같은 방향으로 함께**
  움직일 때의 값이다. 비율 방향은 상쇄가 일어나 그보다 작다. 스크리너가 답한다.
  → 실측 `hand 11.03 · count4 4.80 · gap 0.86/0.39`. 예상대로 작았다 (§8-6).

**적지 못한 위험이 방향이었다.** §8-5에 *"곡률이 작을 위험"*은 적었는데
**"방향이 반대일 위험"은 안 적었다.** 그것이 실현됐다 (§8-8).

### 8-6. 곡률 실측 — 두 축이 더 닫혔다

| 축 | 배포 | `C = K·Var(d)` | ±20% | ±40% | 판정 |
| --- | ---: | ---: | ---: | ---: | :-: |
| **`β hand`** | 1.875 | **11.03** | **1.55** | **6.20** | **살아있다** |
| `β count4` | 1.25 | 4.80 | 0.30 | 1.20 | 경계선 |
| `β gap_bsuccess` | 0.03 | 0.86 | 0.0000 | 0.0000 | **종결** |
| `β gap_success` | 0.03 | 0.39 | 0.0000 | 0.0000 | **종결** |

**asof 두 축은 죽었다.** `C`는 0이 아니지만 β가 0.03이라 **전 구간(0 ~ 0.06)을 훑어도
0.001점 미만**이다. 축의 자연 단위가 곡률만큼 중요하다는 것을 보여주는 사례다.

`hand`가 `count4`보다 2.3배 크다. δ std가 0.01802 vs 0.01314이고 β도 1.875 vs 1.25라
양쪽 모두에서 앞선다.

### 8-7. 스텝을 0.375에서 0.1875로 줄인 이유

목표가 **오늘 안에 신기록**이었다. 신기록 조건은

```
ΔScore = C·Δx·(2u − Δx) > 0    ⟺    u > Δx/2
```

**스텝이 작을수록 손익분기가 낮다.** 그리고 **정보량은 스텝과 무관하다** — LB가 10자리
결정적이라 어느 스텝에서도 `u`를 정확히 역산한다. 즉 스텝은 순전히 점수 결과만 좌우한다.

| β | 손익분기 `β*` | 신기록 확률(사전) | `u=.375` 이득 | 최악(`u=0`) |
| ---: | ---: | ---: | ---: | ---: |
| 2.0000 | 1.9375 (+3%) | 69% | +0.86 | −0.17 |
| **2.0625** | **1.9688 (+5%)** | **66%** | **+1.16** | **−0.39** |
| 2.1250 | 2.0000 (+7%) | 62% | +1.38 | −0.69 |
| 2.2500 | 2.0625 (+10%) | 56% | +1.55 | −1.55 |

### 8-8. 실측 — `1106.5761424262`. **방향이 반대였다**

```
p_bh206.zip   2026-08-24 22:20   LB 1106.5761424262
기준선 adopt = 1109.2714702849   ->   ΔScore = −2.6953
```

**적어둔 최악(`−0.39`)보다 7배 나쁘다.** 이 크기는 `u = 0`으로는 나올 수 없다.
`u < 0` — **최적 β가 배포값 아래에 있다.**

> **자기 정정.** 방향을 위로 잡은 근거는 §8-1의 밴드 규칙(*"허용 구간 최대값 한 칸
> 아래"*)이었다. *"배포값이 구조적으로 보수적이니 최적은 위"*라고 썼다. **틀렸다.**
>
> 그 밴드 규칙은 원우가 `1.5`를 고를 **당시의 fold 곡선**에 대한 것이다. 그 뒤
> `init_score`(§7.109) · soft label(§7.70) · F전문가 α=0.458(어제 채택)이 전부 들어왔다.
> **δ가 설명하던 신호의 일부를 다른 채널이 이미 가져갔다면 최적 β는 내려간다.**
> 특히 `fspec_alpha`를 세 배로 키운 것이 바로 전날 일이고, `hand` δ는 좌우 손잡이 축이라
> F 전문가와 겹칠 여지가 있다.
>
> **"배포값이 보수적으로 골라졌다"는 그 값이 정해진 시점의 성질이지, 지금 스택의
> 성질이 아니다.** 같은 실수를 §3-6(`noid` 꼭짓점이 `c`에 고정이라고 본 것)에서
> 이미 한 번 했다. **다른 축이 움직이면 이 축의 꼭짓점도 움직인다.**

### 8-9. 그래도 축은 살아 있다 — 오히려 더 크다

`ΔScore = C·Δx·(2u − Δx)`를 `C·u`에 대해 풀면 **`C` 가정과 무관한 양**이 나온다.

```
C·u = (ΔScore/Δx + C·Δx)/2 = −6.153
최적에서의 이득 = C·u² = (C·u)²/C = 37.87 / C
```

| `C` 가정 | `u` | `β*` | 최적 적용시 이득 |
| ---: | ---: | ---: | ---: |
| **11.03** (스크리너 실측) | −0.558 | **1.317** | **+3.43** |
| 15 | −0.410 | 1.465 | +2.52 |
| 20 | −0.308 | 1.567 | +1.89 |
| 30 | −0.205 | 1.670 | +1.26 |
| 45 | −0.137 | 1.738 | +0.84 |

**`C`를 어떻게 잡아도 `β*`는 1.875 아래이고 이득은 `+1.3 ~ +3.4`다.**
방향은 확정됐고 크기만 `C`에 달렸다.

> `C = 11.03`은 **`+20%` 방향의 전방차분**으로 쟀다. 지금 그것을 `−` 방향에 외삽하고 있다.
> 곡선이 비대칭이면 실제 `C`가 더 클 수 있고 그러면 `β*`가 1.875에 더 가깝다.
> **`−` 쪽 2점째가 필요하다** (§8-11).

**오늘 −2.70을 주고 `+1.3~3.4`짜리 축의 부호를 샀다.** 챔피언은 `p_adopt`가 유지된다
(DACON은 최고점을 보존한다).

### 8-10. 부수 소득 — `count4`의 방향이 공짜로 나왔다

공통 배율이 최적(`β* = 0.9907`)이라는 §7.131의 결과가 기울기를 묶어 둔다.

```
g·(1.875, 1.25) = 0      ->      g ∝ ±(−1.25, 1.875)
```

`hand`를 올려서 나빠졌으므로 `∂S/∂β_hand < 0`, 따라서 `c > 0`이고 **`∂S/∂β_count4 > 0`**
— **`count4`는 올려야 한다.** 슬롯을 쓰지 않고 두 번째 축의 부호를 얻었다.

다만 `count4`의 `C = 4.80`은 `hand`의 절반 이하이고, ±40%에서 1.20이다. `hand`를
먼저 옮긴 뒤 재측정해야 한다 — §8-8의 교훈이 그대로 적용된다.

**1번의 예상 LB는 `1109.67 ~ 1112.34`다.** 하한이 현 챔피언 위라 — `C`가 30을 넘지

### 8-12. 이 라운드가 남긴 방법론

**① 축의 자연 단위가 곡률만큼 중요하다.** `β gap_bsuccess`는 `C = 0.86`으로 `LGBM wide
몫`(0.6)보다 큰데도 완전히 죽었다. β가 0.03이라 변위가 못 커진다. **`C`만 정렬하면
틀린다** — 라운드 7에서 실제로 출력 버그로 그렇게 정렬했었다.

**② 스텝 크기는 정보량이 아니라 승률을 정한다.** LB가 결정적이라 어느 스텝에서도 `u`가
정확히 나온다. 목표가 "오늘 신기록"이면 스텝을 줄이는 것이 옳고, 실제로 그렇게 했다.
결과가 나빴던 것은 스텝이 아니라 **방향**이 틀려서다 — 스텝을 0.375로 했으면 −1.55가
아니라 **−5.4**였다.

**③ "배포값이 어떻게 골라졌나"는 방향의 근거가 못 된다.** 그것은 값이 정해진 시점의
성질이다. 그 뒤 스택이 바뀌면 꼭짓점이 움직인다. §3-6에서 같은 실수를 했고
(`noid` 꼭짓점이 `c`에 고정이라고 봄), 이번에도 했다.
**방향은 근거가 아니라 측정으로 정해야 한다.**

**④ 한 점은 부호를 사는 값이다.** 졌지만 `C·u = −6.153`이 확정됐고, 기울기 제약이
`count4`의 부호까지 공짜로 줬다. **곡률이 미리 있으면 실패한 프로브도 완전한 정보를 준다.**

> 여전히 유효하고, 오히려 §4-7이 독립적으로 지지한다.

### LB로 prior를 스윕하지 않는 이유 (철회됨 — §4-8 참조)

레벨 손실은 **예측평균 = 실제평균**일 때 정확히 최소가 된다. 따라서 prior를 격자로 쏘고
LB 최고점을 고르면 그 꼭짓점의 x좌표는 **평가 데이터 라벨의 평균값 그 자체**다.
그것을 측정해 전 행의 예측을 이동시키는 것은 규칙이 금지하는
*"전체 평가 데이터의 분포를 이용해 특정 행의 예측값을 보정"*에 해당한다 (원우 규칙 2).

α 스윕과는 성질이 다르다 — α는 두 예측기 중 무엇이 잘 일반화하는지를 고르는 모델 선택이고,
LB가 알려주는 것은 라벨 통계가 아니다.

| | LB가 알려주는 것 | 판정 |
| --- | --- | --- |
| α · 변형 비중 · β · K 스윕 | 어느 설정이 잘 일반화하는가 | 모델 선택 |
| prior 스윕 | **평가 데이터 라벨의 평균값** | 규정 위반 |

### 왜 이 축들이 남아 있었나

전부 **홀드아웃으로 판정돼 닫혀 있던 것**이다.

| 축 | 원래 판정 | 왜 뒤집혔나 |
| --- | --- | --- |
| `MLP_ALPHA` | §7.65 "두 fold 모두 낮추라 함" | 그 표가 soft label·달력드랍 **이전** 측정 |
| 온도 | §7.19 "fold 간 방향 불일치" | **LB는 fold가 하나**라 그 문제가 없다 |
| `noid` 몫 | §7.27 홀드아웃 기각 | 같은 게이트 |

홀드아웃은 이 축들에서 **정점을 낮게 잡거나 fold끼리 싸운다.** LB는 Public이 테스트
100%라 표본 노이즈가 없고, Brier가 2차 손실이라 응답이 **매끈한 포물선**이다.
그래서 2~3점이면 축이 통째로 끝난다.

### 방법론 요약 — 이게 재사용 가능한 자산이다

```
1. 항등식으로 목적함수를 쓴다      BS = Var(p) − 2Cov(p,y) + (p̄−r)² + r(1−r)
2. 조작을 그 항에 대응시킨다        스케일 → Var·Cov 동시 · 혼합 → Cov 재조합
3. 곡선 형태를 이론으로 안다        아핀 변환이면 정확히 2차
4. 현 챔피언을 한 점으로 쓴다       추가 1~2슬롯이면 꼭짓점 확정
5. 곡률을 이론값으로 계산하면       2점으로도 끝난다 (라운드 2가 그랬다)
```

> **REL(캘리브레이션)은 다 짜냈고, 남은 점수는 전부 RES(빈을 가르는 새 순서 정보)에 있다.**

우리 라운드 2가 이걸 실측으로 확인했다. 전역 스케일은 **단조 변환이라 RES를 원리적으로
못 건드리고**, REL만 3.1점 회수하고 끝났다. **우리가 지금까지 딴 +11.6은 전부 REL·혼합 채널이다.**

RES를 올리려면 **행마다 다르고, 현재 빈 안에서 변동하며, y와의 관계가 시즌을 건너 지속하는
새 정보**가 필요하다. 판정 기준은 원우가 정리한 대로다:

> 판정 기준은 "낮은 f_k와의 상관"이 아니라 **"잔차(y−p)와의 상관"**이다.
> 플래툰 δ가 채택된 이유: `asof_*`에 손잡이 분할이 **없어서** 잔차에 신호가 남아 있었다.

그가 §7.95~7.116에서 열두 축을 닫으며 이 기준을 적용했고 전부 기각됐다.
**새 채널을 열려면 새 가설이 필요하고, 현재 팀에 없다.**
