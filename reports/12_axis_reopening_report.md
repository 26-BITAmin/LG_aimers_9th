### 22-6. 이 라운드가 남긴 것

**① 종결에는 베이스를 함께 적는다.** `gap_p_reverse` 는 1115 스택에서 닫혔고 1132 스택에서
열렸다. 라우팅도 같았다. **"닫혔다" 는 "그 베이스에서 닫혔다" 의 줄임말이다.**

**② 상관을 계산했으면 부호까지 읽는다.** §14-6 은 `corr = −0.7430` 을 적어 놓고 양의
격자만 훑었다. **이미 배포된 축과 음의 상관이면 새 축의 β 는 음수일 수 있다.**

**③ 파생 상수는 축마다 다시 만든다.** `k_off` 를 템플릿에서 복사해 스윕 하나를 통째로
버렸다. **재현 관문(기존 축을 다시 만들어 대조)이 없으면 이런 오류는 조용히 지나간다.**

**④ 같은 베이스에서 잰 값끼리만 비교한다.** 서로 다른 베이스의 fold 값과 LB 를 나란히
놓고 결론을 냈다가 판정 기준을 반대로 뒤집을 뻔했다.

**⑤ 우리에게 믿을 만한 홀드아웃이 없다. `fold2024` 도 판정자가 아니다.**

처음에 이 실패를 보고 *"`fold2024` 가 음수면 내지 않는다"* 로 정리했다. 사용자가
*"fold2024 만으로 판정하는 게 정확한가"* 라고 물어 전수로 세니 **반례가 이미 있었다.**

| 사례 | `fold2024` | LB | 일치 |
| --- | ---: | ---: | :-: |
| `gap_reverse` | +1.97 | **+8.68** | ✓ |
| `gap_strike` | −5.49 | **−0.58** | ✓ |
| **`hj07` 트랙맨 잔차** | **+7.01** | **−5.93** | **✗** |

**2/3 이다.** 그리고 부호가 맞아도 **크기는 못 쓴다** — 배율이 `gap_reverse` 4.4,
`gap_strike` 0.11 로 **40배** 벌어진다. 절대값이 더 컸던 `gap_strike` 가 LB 에서는
훨씬 작았다. **후보 간 순위를 못 매긴다.**

게다가 `fold2024` 는 **in-sample** 이다. 원우 §7.27 이 정량화해 뒀다 —
변동폭이 `fold2024` ±2.2~3.3 대 `fold2023` ±5.2~11.3 으로,
*"fold2024 에 판별력이 없다"*.

지금까지 우리가 쓴 판정 기준 **넷이 전부 한 번씩 틀렸다.**

```
양 fold 일치 게이트   gap_success 를 기각했을 것 (역사적 최대 이득)
fold2024 단독        2/3, 크기 배율 40배 산포
fold2023 단독        gap_strike 에서 +6.05 로 더 컸다 (LB 는 음수)
위약 검정            hj07 이 z 2.67 로 통과하고 LB −5.93
```

**그래서 결정을 홀드아웃이 아니라 슬롯 경제로 옮긴다.**

```
채점이 max 다 → 틀려도 점수는 안 깎인다. 비용은 슬롯 하나
물어야 할 것:  "홀드아웃이 통과했나"  가 아니라
              "이 슬롯을 여기 쓰는 것이 다른 후보보다 나은가"
```

운용 규칙 넷.

1. 후보를 여러 개 재서 **순위 없이 목록만** 만든다 (`fold2024` 양수인 것)
2. **크기로 순위를 매기지 않는다** — 배율이 40배 흔들린다
3. 슬롯 여유를 보고 위에서부터 태운다
4. **클래스별로 적중률을 따로 기록한다** — 지금 표본 셋에 클래스가 둘이다

```
고정 δ 스칼라   gap_reverse ✓ · gap_strike ✓     2/2
학습된 층       hj07 ✗                           0/1
```

`fold2024` 가 **δ 계열에서만** 맞았을 수 있다. 표본이 더 쌓여야 안다.

### 23-4. 판정 기준 — 게이트 넷

> **슬롯은 `ΔScore` 를 LB 앵커 닫힌식으로 계산할 수 있는 후보에만 쓴다.**

| | 요건 | 왜 |
| --- | --- | --- |
| **G1** | 모델 형식이 **검증**됐다 — 근사가 아니라 항등식 | 형식이 틀리면 나머지가 무의미 |
| **G2** | 2차항(곡률)이 **라벨 없이** 측정된다 | 라벨을 쓰면 in-sample 암기가 섞인다 |
| **G3** | 1차항(방향)이 **같은 층의 LB 실측점**에서 역산된다 | 다른 층의 Δ 는 전이되지 않는다 |
| **G4** | 예측이 뒤집히는 데 필요한 `C` 배율이 **실측 전이오차(1.41×) 를 넘는다** | 마진을 수치로 남긴다 |

> **G4 의 오차 대용치는 `C` 의 시즌 변동이 아니라 "더미 → 실제 test 전이"다.**
> §10-3 실측 0.711 (라벨없는 `C` 가 40% 과대). 시즌 변동(1.088)을 쓰면
> 마진을 20배 부풀리게 된다 — 라운드 23 초안에서 실제로 그 실수를 했다.

**홀드아웃은 후보 발굴에만 쓴다. 판정에는 쓰지 않는다.**
`fold` 스윕 · 위약 검정 · 마스킹 실험 전부 G2 를 위반한다 (평가 시즌이 챔피언의
in-sample 이다).

**G3 이 없으면 그 축은 슬롯을 못 받는다.** 신규 축은 LB 점이 0개라 원리적으로
G3 을 못 채운다 — 그래서 `gap_reverse`(+8.68) 같은 이득은 **우리 기준으로는
못 잡는다.** 그것을 감수한다. 기준의 목적은 최대 이득이 아니라 **음수 회피**다.

### 23-5. 적용 — 라우팅 축만 통과한다

`predict.py` 두 줄. `R = 0.10 + 0.075t`, `F = 0.40 + 0.10t`.

**G1 — 형식 검증.** 라우팅은 로짓 공간 선형 블렌드라 `p(t)` 가 `t` 에 선형이고,
그러면 `Brier` 는 `t` 에 **정확히** 2차다.

```
Brier(t) = Brier₀ + 2u·M + u²·G        u = t + 0.70,  M = mean(g(p₀−y)),  G = mean(g²)
```

2024 프록시 253,507행에서 네 지점으로 확인:

| 기준현 대비 | rms(g) | corr | 비 |
| --- | ---: | ---: | ---: |
| t −0.90 | 1.20750e−03 | 0.99999985 | 1.000047 |
| t −1.10 | 1.20752e−03 | 0.99999975 | 1.000058 |
| t −1.3333 (경계) | 1.20753e−03 | **0.99999959** | **1.000065** |

**경계까지 선형이다.** 외삽이 근사가 아니다.

**G2 — 라벨 없는 곡률.** `C = K·mean(g²) = 0.5836` (2024) / `0.6347` (2023).
`PROB_SHIFT` 는 확률공간 덧셈 상수라 예측 후 평균 제거가 재보정과 동일하다.

**G3 — LB 앵커.** 라운드 20 의 `hj03_dim8_cold → hj05_r047f330` `+0.7907`.
두 zip 을 바이트 비교해 **라우팅 두 줄 + `PROB_SHIFT` 뿐**임을 확인했다.

```
K·M = (0.7907 − 0.2025·C)/0.9 = 0.7473
검산  ΔScore(u=+0.45) = −0.7907   (실측과 일치)
```

> ★ **2024 라벨이 준 `K·M` 은 −14.71 이다 — 부호가 반대이고 크기가 19.7배다.**
> 홀드아웃을 따랐으면 라운드 20 의 `+0.79` 를 못 먹었다. §15-9 의 규칙
> *"라우팅 가중의 방향은 fold/CV 에서 가져오지 않는다"* 가 수치로 확인됐다.

**꼭짓점은 `t* = −1.98` 로 실현 가능 구간 밖**이다. `R` 이 0 이 되는 `t = −4/3` 이
제약 최적점이다.

| t | R | F | 예측 ΔScore | 손익분기 C배율 |
| ---: | ---: | ---: | ---: | ---: |
| −0.90 | 0.032500 | 0.310000 | +0.276 | 15.9× |
| −1.10 | 0.017500 | 0.290000 | +0.504 | 5.4× |
| **−1.3333** | **0.000000** | **0.266667** | **+0.712** | **2.49×** |

**G4 — 마진. ★ 처음 쓴 계산이 틀렸다.**

오차 대용치로 `C` 의 **시즌 변동**(2023→2024 = 1.088배)을 썼는데, 맞는 대용치는
**더미 → 실제 test 전이**다. 그리고 그 값은 §10-3 이 이미 실측해 뒀다.

```
C_중심 (라벨없음, 2024 더미)   11.04
C_LB   (실제 2025 test 4점 적합) 7.86        비 0.711  — 라벨없는 C 가 40% 과대
```

> §10-3 실무 규칙: *"라벨없는 `C` 는 **후보를 거르는 데** 쓰고, **값을 정하는 데는**
> LB 적합 `C` 를 쓴다."* — **`hj12` 는 라벨없는 `C` 로 값을 정했다. 이 규칙을 어긴다.**

어길 수밖에 없다(라우팅 축은 LB 점이 1개라 `C` 를 적합할 수 없다). 대신 그
전이오차를 봉투로 씌운다. 봉투 = `[0.711, 1.41]` (실측값과 그 역수).

### 23-7. 이 기준으로 남는 것

`hj12` 를 태우면 **라우팅 축은 경계에 닿아 종결된다.** 그 다음 G3 을 채우는 축이 없다.

```
LB 실측점 ≥1 인 축     hand(4점) count4(2점) mlp_alpha(8점) 라우팅(1점) — 전부 최적 도달
LB 실측점 0 인 축      신규 δ · 모델 용량 · 학습 층 — G3 미충족
```

**기준을 지키면 `hj12` 이후 우리가 쓸 슬롯이 없다.** 이건 기준의 결함이 아니라
사실의 보고다 — 남은 이득은 **모델을 바꾸는 쪽**(용량·구조)에 있고, 그건
사후 상수 축이 아니라서 LB 앵커를 만들 수 없다.

기준을 어기고 태울지는 **슬롯 잔량과 팀 조율의 문제**이지 측정의 문제가 아니다.
어긴다면 클래스 전적이 유일한 근거다 — `모델 용량 2/2` 가 가장 높다.

## 라운드 24 — 검증 절차를 코드로 고정한다 (`tools/gate_check.py`)

### 24-1. 왜 기준이 계속 흔들렸나 — 두 층을 한 덩어리로 봤다

라운드 23 까지 "검증"이라는 한 단어로 **성격이 완전히 다른 두 가지**를 불렀다.

| | 무엇 | 성격 | 확실해지나 |
| --- | --- | --- | --- |
| **1층** | 빌드 검증 — *"zip 이 의도한 대로 동작하는가"* | 결정론적 **확인** | **된다** |
| **2층** | 점수 예측 — *"LB 가 오르는가"* | 통계적 **추론** | **원리적으로 안 된다** |

1층은 한 번도 틀린 적이 없다. **틀릴 수 있는 종류가 아니기 때문**이다.
2층을 확실하게 만들려는 시도가 전부 실패했다 (홀드아웃 0/4, 부호 2회 오류).

**그래서 도구는 2층을 판정하지 않는다. 답을 적도록 강제할 뿐이다.**

### 24-2. 1층 — 여덟 항목 (전부 통과해야 태운다)

### 24-3. 2층 — 질문 하나로 줄인다

> **"이 후보가 지려면, 무엇이, 얼마나 틀려야 하는가?"**
> **한 문장으로 답할 수 있으면 태운다. 못 하면 안 태운다.**

`--risk` 와 `--predict` 가 없으면 **도구가 판정을 거부한다.**
`hj07`(−5.93) 과 `hj11`(−1.25) 은 이 문장이 없는 채로 태웠고 둘 다 졌다.

G1~G4 는 별개 규칙이 아니라 **이 질문에 답하기 위한 최소 재료**다.

```
G1 형식 검증      -> "무엇이" 를 특정 가능하게 한다 (틀릴 수 있는 항이 유한개)
G2 라벨없는 곡률   -> 2차항을 in-sample 오염 없이 준다
G3 LB 앵커        -> 1차항을 test 자신에서 준다
G4 봉투           -> "얼마나" 를 숫자로 만든다
```

봉투 하한이 0 이하면 기각한다 — **오차 범위 안에서 지는 후보다.**

## 라운드 25 — 게이트 전면 개정. **LB 앵커는 입장 요건이 아니라 거부권이다**

### 25-1. 라운드 23~24 의 게이트가 틀렸다 — 틀린 목적함수를 최적화했다

혜진님 지적: *"계속 닫은 가설들을 열었더니 점수가 많이 오르잖아."* 맞다.
클래스별로 실측 슬롯당 이득을 세면 결론이 뒤집힌다.

| 클래스 | 슬롯 | 합계 | **슬롯당** | P(Δ>0) | 라운드 23 게이트 |
| --- | ---: | ---: | ---: | ---: | :-: |

| **B 신규 δ 축** | 4 | +9.8225 | **+2.4556** | 50% | ❌ 전부 기각 |

| D 학습된 층 | 1 | −5.9300 | −5.9300 | 0% | ❌ 기각 |

```
A  p_fix_45e9 +0.7506 · hxc +0.03 · rt175 -1.5703 · s41 +0.2469
   s47 +0.2172 · hj05 +0.7907 · hj11 -1.2544
B  gap_reverse +8.6773 · gap_strike -0.58 · gap_bmiddle -2.3338 · middle_rate_sm +4.0590

```

**내 게이트가 통과시키는 유일한 클래스가 순 −0.79 다.** 유일한 음수 클래스 D 다음으로 나쁘다.

#### 왜 이렇게 됐나

`P(Δ>0)` 를 최적화했다. **`max` 채점에서 최적화해야 하는 것은 `E[Δ]` 다** —
지는 비용이 점수가 아니라 **슬롯 하나**이기 때문이다.

```
A  예측 가능하다. 그래서 앵커를 만들 수 있다. 그리고 **작다** (전부 소수점)
B·C 예측 불가능하다. 앵커가 없다. 그리고 **크다** (+8.68 · +7.67 · +4.06 · +3.32)
```

**예측 가능성과 크기가 역상관이다.** 사후 상수 축은 이미 최적 근처라 예측이 쉽고
남은 헤드룸이 없다. 새 통로는 헤드룸이 크고 그래서 앵커가 있을 수 없다.
앵커를 입장 요건으로 걸면 **헤드룸이 남은 축을 정의상 전부 배제한다.**

### 25-3. 종결 기준도 같이 고친다

재개방 전적이 이 축의 증거다.

| 닫힌 근거 | 재개방 이득 |
| --- | ---: |
| 원우 `ablate17` emb8 — 교란 4변경 팔 | **+7.67** |
| 우리 큐 #20 라우팅 — LB −1.5703 | +1.26 |
| 우리 §14-6 `gap_p_reverse` — 홀드아웃 널 | **+8.68** |
| 원우 §7.91 컬럼 — *"참고, 질문 밖"* | **+4.06** |
| | **+21.67** |

> **홀드아웃 널로 축을 닫지 않는다. 보류만 한다.**
> **LB 음수 한 번으로도 닫지 않는다** — 방향·층·측정설계를 먼저 본다
> (라우팅이 −1.5703 으로 닫혔다가 +1.26 을 냈다. 축이 아니라 **방향**이 틀렸었다).
> **닫는 근거는 LB 앵커가 "최적에 도달했다"고 말할 때 하나뿐이다.**

앵커가 실제로 닫은 축: `count4`(β\*=1.238, `hj11` 이 확인) · `hand`(β\*=1.054) ·
`mlp_alpha`(α\*=0.74499) · 라우팅(`hj12` 로 경계 도달 예정). **이것이 앵커의 본업이다.**

### 25-4. 개정된 2층 절차

```
1  1층 빌드 검증 8항목      — 변경 없음. 이진값이고 공짜다
2  클래스 판정              — A/B/C/D 중 어디인가
3  클래스 기대값 음수?      -> 기각 (D)
4  LB 앵커가 있나?
     있고 음수 예측         -> 거부권. 기각
     있고 양수 예측         -> 통과. 크기를 그대로 씀
     없음                   -> 통과. 클래스 슬롯당 기대값을 크기 추정으로 씀
5  기대값 큰 순으로 슬롯 배분
```

**"이 후보가 지려면 무엇이 얼마나 틀려야 하는가" 는 유지한다** — 단
**통과 요건이 아니라 앵커가 있을 때의 거부권 판정용**이다.
