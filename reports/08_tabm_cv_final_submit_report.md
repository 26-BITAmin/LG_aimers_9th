## 08b 전체 학습 구성

| 모델 | 학습 범위 | 행 수 | 피처 | 학습 시간 |
| --- | --- | ---: | ---: | ---: |
| LightGBM | 2019~2024 R | 1,314,088 | 76 | 42.69초 |
| CatBoost base | 2019~2024 R/F | 1,475,092 | 113 | 12.86초 |
| CatBoost F route | 전체 R + 2024 F | 1,344,098 | 113 | 11.55초 |
| TabM | 2019~2024 R | 1,314,088 | 수치 163 + 범주 19 | 32.43초 |

최종 조합은 다음과 같다.

- Tree base: LightGBM 65% + 라우팅 CatBoost 35% logit blend
- R: Tree base 70% + Brier-loss TabM 30% probability blend
- F: Tree base 100%, TabM 미적용
- TabM: `season`, `game_type` 제외, `k=32`, 3 blocks, width 256, dropout 0.1, 1 epoch
- TabM target encoding 학습: 각 행보다 과거 시즌의 정답만 사용
- 2025 추론 통계: 2019~2024 R 학습 정답만 사용하고 평가 행 간 집계는 사용하지 않음

## 하락 원인 해석

1. **OOF 개선 폭이 작았다.** 선택 후보의 최근 R Brier 개선은 `2.67e-5`였고, 2024 단독 개선은 `1.29e-5`였다. 2025 분포 이동에서 부호가 바뀔 수 있는 규모다.
2. **TabM 단독 성능은 tree보다 낮았다.** 08의 이득은 강한 새 단독 모델이 아니라 OOF residual의 미세한 상보성에서 발생했다. 이 상관 구조가 2025에도 유지된다는 보장은 없다.
3. **전체 재학습 모델은 단일 seed·단일 checkpoint다.** fold별 checkpoint 평균이 아니라 최근 fold에 맞춘 1 epoch 전체 모델이므로 OOF 예측과 완전히 같은 분산 구조를 기대할 수 없다.
4. **CatBoost GPU 재학습본도 byte-identical하지 않다.** 03과 04의 LightGBM 파일은 SHA-256이 같지만 두 CatBoost 파일은 다르다. 패키지 내부 F 고정 검사는 통과했지만, 04의 tree가 03 제출 파일과 바이트 단위로 동일한 것은 아니다. 따라서 Public 변화 전부를 TabM 하나에 정밀 귀속할 수는 없다.
5. **Public 결과로 10%·20%를 다시 고르면 리더보드 과적합이 된다.** 낮은 비중도 OOF에서는 통과했지만, 30%의 Public 결과를 본 뒤 비중만 바꿔 반복 제출하는 것은 기대 개선보다 선택 편향이 커진다.

## 결정 및 다음 단계

1. 제출 선택을 `submit_03_fix.zip`으로 되돌리고 `submit_04.zip`은 실험 기록으로만 보존한다.
2. 현재 단일 TabM과 10~40% 단순 혼합은 더 이상 주력 경로로 확장하지 않는다.
3. 다음 혼합 실험에서는 **03의 native tree 파일을 그대로 재사용**해 GPU CatBoost 재학습 변동과 새 모델 효과를 분리한다.
4. 09에서는 작은 blend 조정보다 모델의 절대 성능 상한을 올리는 실험을 우선한다. 최근성 가중치·tree 용량·선수 ID 처리·loss를 넓게 비교하고, seed 안정성과 2024 최악 fold를 통과한 모델만 제출 후보로 둔다.
5. 새 모델은 단독 R Brier가 기존 tree와 비슷하거나 더 좋아야 한다. 낮은 상관만으로 앙상블 후보를 채택하지 않는다.
6. 팀 모델과의 최종 앙상블은 우리 독립 솔루션의 OOF 품질을 먼저 끌어올린 뒤 동일 행 OOF로 판단한다.
