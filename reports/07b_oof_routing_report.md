## 사전 고정 라우팅

07 결과를 분석한 뒤, 07b 점수를 읽기 전에 다음 네 경로를 고정했다.

| 경로 | R CatBoost | F CatBoost | 역할 | 자동 선택 |
|---|---|---|---|---:|
| `current_r__current_f` | current | current | 기준 | 제외 |
| **`current_r__latest_f1_f`** | current | `shared_latest_f1` | primary | 허용 |
| `current_r__fast_decay_f` | current | `shared_f_fast_decay` | backup | 허용 |
| `current_r__r_only_f` | current | `r_only` | 불안정 진단 | 제외 |

선택은 OOF 최저 점수순으로 다시 탐색하지 않았다. 고정 우선순위는 `primary → backup → base`다.

primary 또는 backup은 다음 조건을 모두 만족해야 한다.

1. 모든 R CatBoost 예측이 기준과 정확히 같다.
2. 2023·2024 pooled 전체와 F Brier가 기준보다 낮다.
3. 2022·2023·2024 각 fold의 전체 Brier가 어느 하나도 악화되지 않는다.
4. 세 fold의 F Brier가 어느 하나도 악화되지 않는다.
5. test의 다른 행을 이용하지 않고 현재 행의 `game_type`만 사용한다.

혼합은 05 이후 유지한 LightGBM 65% + 선택 CatBoost 35% logit 평균이다. 추가 보정이나 혼합비 grid는 없다.

## 예측 변화 규모

primary와 기준의 최근 F 예측 상관은 `0.972575`, 평균 절대 확률 차이는 `0.007113`이다. 최근 전체 행에서는 상관 `0.996761`, 평균 절대 차이 `0.000794`다.

이는 다음을 의미한다.

- R 88.84%는 예측을 그대로 유지한다.
- F에서도 완전히 다른 모델로 교체하는 것이 아니라 기존과 높은 상관을 가진 공유 모델을 사용한다.
- F-only 전문가처럼 확률을 크게 흔들지 않고 최근 F 학습 범위만 제한한다.
- 전체 개선 폭이 크지 않은 대신 기존 제출의 안정적인 R 성능을 보존한다.

backup은 최근 F 평균 절대 변화가 `0.005053`으로 primary보다 더 보수적이고 세 fold를 모두 개선한다. 최종 primary 학습이나 패키징에 문제가 생길 때만 사용한다.

## 최종 학습 레시피

다음 제출 후보는 모델 세 개를 사용한다.

### LightGBM

- 제출 2와 동일
- 학습: 2019~2024 R 행만 사용
- 최근성 half-life: 2.5년, 기준 시즌 2025
- 피처: `pitchmix_shape`, 선수 ID 제외, season 포함
- 500 estimators

### 기본 CatBoost

- 제출 2와 동일
- 학습: 2019~2024 R/F 전체
- 최근성 half-life: 0.5년, 기준 시즌 2025
- 피처: `all_new`, 선수 ID 포함, season·`game_type` 제외
- 85 iterations

### F 라우팅 CatBoost

- 학습: 2019~2024의 모든 R 행 + 2024 F 행만 사용
- 과거 F 2019~2023은 제외
- 최근성 half-life: 0.5년, 기준 시즌 2025
- 피처·파라미터: 기본 CatBoost와 동일
- `game_type`은 라우팅 조건으로만 사용하고 모델 피처에서는 제외
- 추론 확률은 F 행에서만 사용

기본 CatBoost와 F 라우팅 CatBoost는 학습 target prior가 다르다. `smoothed_*` 피처가 prior를 사용하므로 최종 스크립트는 두 CatBoost별 prior를 따로 저장하고 각각의 피처 행렬을 만들어야 한다. 같은 113개 열 이름만 맞추고 하나의 prior를 공유하면 OOF 레시피가 재현되지 않는다.

최종 확률은 다음과 같다.

```text
cat_probability = where(game_type == "F", f_route_cat, base_cat)
prediction = sigmoid(0.65 × logit(lgbm) + 0.35 × logit(cat_probability))
```

## 최종 제출 노트북 필수 검사

1. 세 모델의 전체 학습 행 수·target rate·sample-weight 범위를 기록한다.
2. LightGBM과 두 CatBoost의 피처 열·개수·categorical 열을 저장하고 제출 스크립트와 exact match를 확인한다.
3. 세 모델 native 저장 후 재로딩 예측 차이가 0인지 확인한다.
4. 기본 CatBoost와 F CatBoost의 target prior를 별도 저장한다.
5. R 행에서 기존 제출 2와 동일한 CatBoost 경로를 사용하는지 확인한다.
6. F 행에서만 새 CatBoost 경로를 사용하는지 synthetic R/F 행으로 검사한다.
7. 셔플·청크·단일 행 추론 불변성을 다시 검사한다.
8. 제출 ZIP 내부에는 `model/`, `script.py`, `requirements.txt`만 포함한다.
9. 제출 ZIP 파일명은 30자 이하로 한다. 예시는 `submit_03.zip`이다.
10. 제출 전에 평가 스크립트를 별도 임시 디렉터리에서 end-to-end 실행한다.
