# 10. `MLP_ALPHA` 프로브 — LB 5점 측정 완료

**2026-08-20 · DIRECTION.md 후보 #1 · 결론: 배포값 0.40은 최적이 아니다**

> **한 줄 요약** — 홀드아웃은 α를 낮추라고 했고 원우는 따르지 않았다. **원우가 옳았다.**
> 그런데 충분히 가지 않았다. LB는 α에 대해 **완벽한 2차곡선**(R²=1.00000000)이고
> 꼭짓점은 **α ≈ 0.745**다. 배포값 0.40 대비 예측 이득 **+8.5점**,
> 실측된 α=0.60만으로도 **+6.98점 (신기록 1074.5321)**.

챔피언 스택(`wonwoo` s24, LB 1067.5494)에서 **α만 바꾼** 제출 zip 5개를 만들었다.
`§7.65`의 미결 — _"두 fold가 모두 α를 낮추라는데 배포는 0.40이다"_ — 을 LB로 판정한다.

## 1. 실험 설계

### 왜 이 축인가

|                       | 주장                                                   | 예측             |
| --------------------- | ------------------------------------------------------ | ---------------- |
| 홀드아웃 (§7.65 측정) | 두 fold 모두 α↓ (f2023 +9.25, f2024 +1.17)             | 0.30 이하가 좋다 |
| 원우 판단             | 홀드아웃이 MLP 비중을 과소평가한다 (전이 배율 2.6·6.7) | 0.40 이상이 좋다 |

**배포값 0.40 아래만 재면 "0.40이 최적"과 "더 올렸어야 했다"를 구분할 수 없다.**
그래서 0.20~0.60을 균등 간격으로 걸쳤다.

Public이 테스트 100%라(§DIRECTION.md 2절) 표본 노이즈가 없다 — 홀드아웃에서
잡음 바닥(4~9점)에 묻히던 차이가 여기서는 그대로 측정된다.

### 실행 환경

로컬 macOS(M1)에서는 **LightGBM/PyTorch `libomp` 충돌**로 학습이 불가능했다.
LGBM 20개 완료 직후 torch 첫 병렬 연산(`index_kernel`)에서 `__kmp_join_barrier`
데드락, 임포트 순서를 바꾸면 SIGSEGV. `KMP_DUPLICATE_LIB_OK=TRUE`는 "조용히 틀린
결과"를 낼 수 있어 쓰지 않았다.

Colab으로 옮긴 것은 우회가 아니라 **재현 충실도 향상**이다.

|             | 원우 (기준)  | M1 로컬         | Colab (사용)           |
| ----------- | ------------ | --------------- | ---------------------- |
| CPU         | x86_64       | arm64 (불가)    | x86_64                 |
| torch       | `2.13.0+cpu` | 플레인 arm64 휠 | `2.13.0+cpu` 정확 일치 |
| libomp 충돌 | 없음         | 치명적          | 없음                   |

Colab Pro 고용량 RAM 런타임(8 vCPU). `num_threads=6`(LGBM)·`THREADS=4`(MLP)는
코드 고정이라 **코어 수가 달라도 모델은 바뀌지 않는다** — 속도만 달라진다.

도구는 전부 `hyejin` 브랜치에 있고 원우 파일은 읽기·실행만 했다
(`tools/probe_alpha.py`, `tools/build_probe.py`, `tools/verify_zip.py`,
`notebooks/10_alpha_probe_colab.ipynb`).

### 2-1. `logit_delta`가 α마다 재해결됐다 — 프로브 유효성의 핵심

|    α | pred_mean (보정 전) | `logit_delta` |     차분 |
| ---: | ------------------: | ------------: | -------: |
| 0.20 |              0.4845 |      −0.03832 |          |
| 0.30 |              0.4842 |      −0.03737 | +0.00095 |
| 0.40 |              0.4840 |      −0.03643 | +0.00094 |
| 0.50 |              0.4838 |      −0.03549 | +0.00094 |
| 0.60 |              0.4835 |      −0.03455 | +0.00094 |

**완벽하게 단조·선형이다.** `artifacts.joblib`의 `mlp_alpha`만 갈아끼웠다면 델타가
5개 모두 같았을 것이다. `train._finish()`가 블렌드 **이후** 로짓으로
`solve_delta(base + raw_ref, 0.475)`를 매번 다시 풀었다는 직접 증거다.

> 이것이 이 프로브에서 가장 중요한 함정이었다. α를 바꾸면 블렌드 로짓이 바뀌고
> → delta도 달라져야 한다. 안 고치면 prior가 어긋나 `BSS ≈ −400,000 × (편차)²`로
> 크게 잃는다. `--artifacts-only` 경로가 `_finish()`를 공유하기 때문에 자동으로 해결된다.

### 2-2. 레벨이 다섯 개 모두 동일하다 — 설계상 이점

`245,789행 mean`이 **0.4801로 전부 같다.** `solve_delta`가 예측 평균을 목표 prior에
고정하므로 α가 바뀌어도 레벨이 움직이지 않는다.

> **다섯 제출의 레벨 성분이 동일하므로 LB 점수 차이는 전부 해상도(refinement) 차이다.**
> §7.65가 물은 "α가 refinement에 어떻게 기여하는가"를 레벨 교란 없이 순수 측정한다.

### 2-3. 모델 재사용 확인

`lgbm_*.txt` 20개의 바이트 크기가 5개 zip에서 **완전히 동일**하다
(`lgbm_base_1234.txt = 1,180,886` 등). `artifacts.joblib`만 3바이트 내외로 다르다
(α + delta). `MLP_ALPHA`가 `train._TRAIN_SHAPING`에 없으므로 `--artifacts-only`가
안전하게 모델을 재사용했다 — 로그의 `참조 행렬 해시 일치 → 저장된 모델 재사용`.

α 변형 1회당 **42~47초** (전체 학습 대비 §7.66의 26분 → 38초와 같은 규모).

## 3. 행 독립성 — 잔차의 기전을 확정했다

`wonwoo:rowindep.py`는 `== 0.0`을 요구하지만 Colab에서는 잔차가 남았다.
**α에 정비례한다**는 것이 결정적이다.

|    α |    셔플 |    청크 | 셔플 ÷ α |
| ---: | ------: | ------: | -------: |
| 0.20 | 4.3e-09 | 2.3e-09 | 21.5e-09 |
| 0.30 | 6.4e-09 | 3.4e-09 | 21.3e-09 |
| 0.40 | 8.5e-09 | 4.5e-09 | 21.3e-09 |
| 0.50 | 1.1e-08 | 5.6e-09 | 22.0e-09 |
| 0.60 | 1.3e-08 | 6.7e-09 | 21.7e-09 |

α는 **MLP의 블렌드 비중**이다. 잔차가 α에 정비례한다는 것은 노이즈가 전적으로
**MLP 순전파에서 발생**한다는 뜻이고, 역산하면 MLP 로짓 자체의 잔차는 약 **2.1e-08**이다.
청크가 셔플의 정확히 절반인 것도 재배치 횟수가 적은 것과 일관된다.

`mlp_infer.py`의 주석이 같은 현상을 기록해 뒀다:

> 패딩이 없으면 행 순서 독립성 검사가 1e-8 수준에서 실패한다. **정보 누출이 아니라
> BLAS 때문이다** — 행렬 모양이 바뀌면 블로킹·벡터화 경로가 달라지고 float32 덧셈은
> 결합법칙이 성립하지 않는다. 실측 `7.45e-09`

원우는 배치 패딩(`BATCH=8192`)으로 자기 환경(Windows x64, 16코어)에서 0을 달성했다.
Colab은 OpenBLAS + 8스레드라 잔차가 남는다. **BLAS 구현마다 다르다** — M1(Accelerate)에서
같은 형태를 재현하니 패딩 유무와 무관하게 0이 나왔다.

### 판정 기준

```
진짜 누출 (다른 행의 통계 사용) : 1e-3 ~ 1e-1
float32 누산 순서              : 1e-9 ~ 1e-8   ← 여기 (float32 eps 1.2e-7 보다도 작다)
```

검증 임계값을 `TOL = 1e-6`으로 뒀다 — 노이즈의 100배, 실제 누출의 1/1000이라 둘을
확실히 가른다. **규정 위반이 아니다**: 규칙이 금지하는 것은 다른 행의 정보로 예측을
보정하는 것이고, 2e-08 로짓 잔차는 그 기전으로 발생할 수 없는 크기다.

### 재현 판정 — 통과 (사전 기준 ±2점, 실측 0.00013점)

```
원우 s24 (Windows x64, torch 2.13.0+cpu)   1067.5494247314
p_a40    (Colab  x86_64, torch 2.13.0+cpu)  1067.5492949006
차이                                         0.0001298308
```

사전 임계값의 **1/15,000** 수준이다. Brier로 환산하면 약 `3e-10` — 사실상 같은 예측이다.

**세 가지가 동시에 확정됐다.**

1. **챔피언 스택 전체가 재현된다.** LGBM 20 + MLP 8 + δ 4축 + prior shift가 다른 OS·다른
   BLAS에서 재생됐다.
2. **§4의 미결(로짓 상관 0.949 vs 0.950)이 풀렸다.** s12/s24 스택 차이 때문에 확증이
   못 된다고 적어뒀는데 LB가 직접 답했다. MLP 8멤버가 블렌드의 40%인데 0.00013점
   차이라면 가중치가 사실상 동일하다.
3. **잔차 크기가 §3과 앞뒤가 맞는다.** LB 차이 0.00013점을 역산하면 행당 평균 `~3e-10`이고,
   §3에서 잰 행 재배치 노이즈(α=0.40에서 최대 `8.5e-09`)와 같은 자릿수다.
   모델이 다른 것이 아니라 마지막 자리만 흔들린 것이다.

→ **DIRECTION.md 2층(챔피언 컴포넌트 이식) 진입 가능.** 사전 규칙대로 판정한다.
→ 남은 α 4장의 비교가 유효하다.

평가 서버(6 vCPU) 추론 36초 / 600초 = 6%.

### 5-1. 사전 고정한 해석 규칙과 그 적용

결과를 보기 **전에** 아래를 고정했다. 사후에 기준을 만들지 않기 위해서다.

**A. `p_a40` vs 1067.5494 — 재현 오차** → **±2점 이내 판정, 실측 0.00013점**

| 결과               | 해석                                  | 다음 행동                 | 적용     |
| ------------------ | ------------------------------------- | ------------------------- | -------- |
| α↓ 일수록 높음     | 홀드아웃이 옳았다                     | 0.15 이하 탐색            |          |
| 0.40 근처 최고     | 원우가 옳았다                         | 축 종결                   |          |
| **α↑ 일수록 높음** | **원우 이론이 맞는데 더 갔어야 했다** | **0.70~0.80 추가 프로브** | **이것** |

### 5-2. 곡선은 완벽한 2차식이다

| 구간        |    증분 | 2차 차분 |
| ----------- | ------: | -------: |
| 0.20 → 0.30 | +7.0540 |          |
| 0.30 → 0.40 | +5.6293 |  −1.4248 |
| 0.40 → 0.50 | +4.2041 |  −1.4252 |
| 0.50 → 0.60 | +2.7787 |  −1.4253 |

2차 차분이 **소수 넷째 자리까지 일정**하다.

```
score(α) = −71.255·α² + 106.170·α + 1036.482
  R² = 1.00000000        잔차 최대 |r| = 0.0001
  꼭짓점  α* = 0.7450    예측 최고점 = 1076.030   (배포 0.40 대비 +8.481)
```

**이건 우연이 아니라 구조적이다.** Brier는 예측에 대한 2차 손실이고, 블렌드는 로짓
공간에서 α에 선형이다. 예측 확률이 좁은 띠(`0.32~0.66`)에 몰려 있어
`σ'(z) = p(1−p) ∈ [0.218, 0.250]`로 거의 일정하므로, **p는 α에 대해 국소적으로 선형**이고
따라서 **Brier는 α의 2차식**이 된다. BSS는 Brier의 선형변환이므로 그대로 2차식이다.

> 이론적 근거가 있는 형태라 외삽의 신뢰도가 단순 곡선적합보다 높다. 다만 α\*=0.745는
> 측정 상단(0.60)에서 0.145 밖이므로 **sigmoid 비선형이 커지면 휘어질 수 있다.** 실측이 필요하다.

|        α |   예측 score |  0.40 대비 |
| -------: | -----------: | ---------: |
|     0.65 |     1075.387 |     +7.838 |
|     0.70 |     1075.886 |     +8.337 |
| **0.75** | **1076.028** | **+8.479** |
|     0.80 |     1075.815 |     +8.265 |
|     0.85 |     1075.245 |     +7.695 |

꼭짓점 주변이 매우 평평하다 — 0.70~0.80 구간의 예측 폭이 **0.2점**뿐이다.
α를 소수점 둘째 자리까지 정밀하게 맞출 실익은 작다.

### 5-3. 홀드아웃이 이 축에서 **부호가 반대**다

§7.65의 홀드아웃 측정과 LB 실측을 나란히 놓으면:

|    α |  f2023 Δ |  f2024 Δ |   **LB Δ** |
| ---: | -------: | -------: | ---------: |
| 0.20 | (미측정) | (미측정) | **−12.68** |
| 0.25 |   +12.58 |    +0.93 |   (미측정) |
| 0.30 |    +9.25 |    +1.17 |  **−5.63** |
| 0.35 |    +5.05 |    +0.86 |   (미측정) |
| 0.40 |        0 |        0 |          0 |
| 0.50 |   −12.68 |    −3.40 |  **+4.20** |
| 0.60 | (미측정) | (미측정) |  **+6.98** |

**두 fold가 모두 α↓를 가리켰는데 LB는 α↑다.** 크기만 틀린 게 아니라 방향이 뒤집혔다.
α=0.50에서 특히 극적이다 — 홀드아웃 f2023이 `−12.68`인데 LB는 `+4.20`이다.

이것은 원우가 §7.65에서 *"홀드아웃은 MLP 비중을 체계적으로 과소평가한다"*고 판단하고
두 fold를 모두 거스른 결정이 **옳았음을 실측으로 확인**한 것이다. 근거가 전이 배율 2점뿐이라
"측정이 아니라 판단"이라고 기록했는데(§DIRECTION.md 6-1), 그 판단이 맞았다.

동시에 이것은 원우 본인이 s16~s19에서 발견한 _"홀드아웃 순위와 LB 순위의
Spearman ρ = −0.6"_ 현상의 연장선이다. **MLP 비중 축에서는 홀드아웃을 판정에 쓰면 안 된다.**

### 5-4. 새 챔피언은 기존 챔피언과 무엇이 다른가

`p_a60.zip`과 원우 `s24_nocal62a8.zip`의 차이는 **설정 상수 하나**다.

| 구성 요소            | s24 (기존)                                            | p_a60 (신규) | 차이                             |
| -------------------- | ----------------------------------------------------- | ------------ | -------------------------------- |
| **`MLP_ALPHA`**      | **0.40**                                              | **0.60**     | **유일한 원인 변경**             |
| `logit_delta`        | −0.03643                                              | −0.03455     | α 변경에 따라 자동 재해결 (파생) |
| LightGBM 부스터 20개 | base/wide/extra/lowff × 5시드                         | 동일         | 바이트 단위 동일                 |
| MLP 멤버 8개         | emb4×5 + noid×3                                       | 동일         | 동일 파일                        |
| 피처                 | 78개 (`game_type`·`game_month`·`game_dayofweek` 드랍) | 동일         |                                  |
| δ 축                 | hand β1.875, count4 β1.25                             | 동일         | 셀 1,571 / 3,105                 |
| 시즌 진행분 축       | gap_success β0.03, gap_bsuccess β0.03                 | 동일         |                                  |
| F 오염 보정          | 피처값 보정 (p·b 축)                                  | 동일         |                                  |
| soft label           | 2019–22 F & y=1, 71,199행                             | 동일         | h 4개 값 동일                    |
| `TARGET_PRIOR_2025`  | 0.475                                                 | 동일         |                                  |
| recency half-life    | 0.5                                                   | 동일         |                                  |

**학습을 다시 하지 않았다.** `--artifacts-only` 경로로 저장된 모델 28개를 그대로 재사용하고
아티팩트만 다시 만들었다(42~47초). §2-3에서 `lgbm_*.txt` 20개의 바이트 크기가 모든 zip에서
동일함을 확인했다.

즉 **원인 귀속이 완전하다.** 다른 실험처럼 "피처도 바꾸고 파라미터도 바꿨는데 점수가 올랐다"가
아니라, 바꾼 것이 정확히 하나이므로 +6.98점 전부가 α에 귀속된다.

### 5-5. 왜 점수가 올랐는가

최종 예측은 이렇게 계산된다. **α가 등장하는 곳은 첫 줄뿐이다.**

```
z = (1−α)·z_lgbm + α·z_mlp          ← 여기만 바뀌었다
z = z + δ(hand) + δ(count4) + gap_success + gap_bsuccess
p = sigmoid(z + logit_delta)
```

#### 레벨이 아니라 해상도가 올랐다

245,789행 예측 평균이 다섯 제출 모두 `0.4801`이다(§2-2). `solve_delta`가 예측 평균을
목표 prior에 고정하기 때문이다. Brier 손실은 레벨 성분과 해상도 성분으로 분해되는데,
**레벨이 묶여 있으므로 +6.98점은 전부 해상도 개선**이다.

절대 크기로는 다음과 같다(`BS_ref = r(1−r) ≈ 0.2494`, BSS 1점 = Brier `2.49e-06`):

| 변화                    |   ΔBSS |   ΔBrier |
| ----------------------- | -----: | -------: |
| α 0.40 → 0.60 (실측)    |  +6.98 | 1.74e-05 |
| α 0.40 → 0.745 (예측)   |  +8.48 | 2.11e-05 |
| α 0.20 → 0.60 (전 구간) | +19.67 | 4.90e-05 |

#### 최적 비중이 0.5를 넘는다는 것의 의미

2차 손실에서 두 예측기를 `(1−α)L + αM`으로 섞을 때 최적 비중은

```
α* = (Var(e_L) − Cov) / (Var(e_L) + Var(e_M) − 2·Cov)
```

이고, **두 오차 분산이 같으면 상관과 무관하게 항상 `α* = 0.5`**다(ρ=0.5/0.8/0.95 모두
0.5000으로 검산). 실측 `α* = 0.745 > 0.5`이므로 다음이 따라온다.

> **MLP 단독이 LightGBM 20개 앙상블보다 2025 평가 데이터에서 더 정확하다.**

이것은 해석이 아니라 위 식에서 나오는 필연이다.

#### 왜 이렇게 작은 차이가 비중을 크게 움직이는가

두 예측기의 로짓 상관이 `0.949`로 매우 높다. 상관이 높을수록 최적 비중은 정확도 차이에
극단적으로 민감해진다(ρ = 0.949 기준):

| sd(e_MLP) / sd(e_LGBM) |       α\* |
| ---------------------: | --------: |
|                  1.000 |     0.500 |
|                  0.990 |     0.598 |
|              **0.975** | **0.747** |
|                  0.950 |     0.990 |

**MLP 오차 표준편차가 2.5%만 작으면 α\* = 0.747**이고, 이는 실측 `0.745`와 거의 정확히
일치한다. 1%만 달라도 최적 비중이 0.5에서 0.6으로 움직인다.

같은 이유로 꼭짓점 주변이 평평하다 — 0.70~0.80 구간의 예측 폭이 0.2점뿐이다(§5-2).

#### 근본 원인은 아직 모른다

"왜 2025에서 MLP가 LGBM보다 정확한가"는 이번 실험이 답하지 않는다. 후보는 셋이고
현재 근거로는 구분할 수 없다.

1. **학습 데이터 범위** — 배포 모델은 2019~2024 여섯 시즌, fold2024는 다섯 시즌이다.
   MLP가 추가 시즌에서 더 이득을 볼 수 있다.
2. **정규화 강도** — MLP는 dropout 0.3, weight decay 1e-2, 6~9 epoch로 강하게 억제돼 있다.
   분포 이동에 덜 무너질 수 있다.
3. **ID 암기의 노후화** — LightGBM은 `pitcher_id`를 raw 정수로 분할해 사실상 암기한다.
   그 암기가 새 시즌에서 빨리 낡을 수 있다.

구분하려면 별도 실험이 필요하다. 다만 **어느 쪽이든 실무 결론은 같다** — §7-4 참조.

### 7-1. 공유 (최우선)

`MLP_ALPHA`는 원우 라인의 배포 상수이고, 그가 §7.65에서 홀드아웃을 거스르며 0.40을
유지한 항목이다. **판단은 옳았지만 값은 낮았다**는 실측이 나왔으므로 본인이 알아야 한다.
`config.MLP_ALPHA`를 0.60 이상으로 올리는 것만으로 그의 스택도 +7점을 얻는다.

### 7-2. 다음 프로브 — α 0.70 / 0.75 / 0.80 (3슬롯)

꼭짓점 예측이 0.745이고 0.70~0.80 구간 예측 폭이 0.2점뿐이므로 **3점이면 충분하다.**
2차식이 그대로 유지되는지 확인하는 것이 주목적이고, 휘어지면 그 자체가 정보다.

예상 이득은 `p_a60` 대비 **+1.3~+1.5점**. 크지 않지만 `--artifacts-only` 38초 경로라
비용이 거의 없다. 이미 학습된 모델(`models/a40`)을 재사용하면 된다.

### 7-3. DIRECTION.md 갱신

- **§6 후보 #1 → 해결.** "α 0.40 → 0.30"이 아니라 **"α 0.40 → 0.60~0.75"**였다.
  방향을 반대로 적었으므로 정정해야 한다 — 홀드아웃 표만 보고 후보를 세운 것이 원인이다.
- **§5 2층(이식) → 진입 가능.** 재현 오차 0.00013점으로 사전 기준(±2점)을 통과했다.
- **§8 판정 게이트에 단서 추가.** MLP 비중 축에서는 홀드아웃 부호가 LB와 반대다.
  조건 ②(두 fold 부호 일치)를 이 축에 적용하면 정답을 기각하게 된다.

### 7-4. 전략적 함의 — 팀의 멘탈 모델이 뒤집혔다

원우 스택은 **LightGBM이 본체, MLP가 추가 멤버**로 지어졌다. §7.16에서 나중에 붙였고
α=0.30으로 시작해 §7.17에서 0.40으로 올린 것이 전부다. 그런데 최적 비중이 0.745라면
**MLP가 본체이고 트리가 보조**다.

이 관점에서 §7.18~7.33의 "노브 13종 전패"가 다시 읽힌다.

| 튜닝 대상                   | 실험       | 결과                     | 그 축의 블렌드 비중 |
| --------------------------- | ---------- | ------------------------ | ------------------: |
| LightGBM 재튜닝 9종         | §7.18      | 9전 9패                  |     60% (당시 기준) |
| 라운드 수·용량·단조제약·bin | §7.28~7.31 | 전부 기각                |                 60% |
| MLP 깊이·폭                 | §7.25      | "깊이는 공짜, 폭은 재앙" |                 40% |
| MLP 수치임베딩 PLE/RFF      | §7.26      | 기각                     |                 40% |
| MLP 멤버 비율               | §7.27      | 기각                     |                 40% |

트리 쪽은 13종을 훑었지만 MLP 쪽은 상대적으로 덜 파였다. **비중이 큰 쪽이 MLP였다면
탐색 배분이 반대였어야 한다.**

α를 0.60에서 0.745로 정밀하게 맞춰 얻을 수 있는 것은 **+1.5점**이다(§5-2).
반면 **MLP 자체의 용량·구조 축은 아직 열려 있고**, 그쪽이 남은 90점의 후보로 더 유망하다.
§5-5의 근본 원인 후보 셋 중 무엇이 맞든 이 결론은 바뀌지 않는다.

DIRECTION.md §6-2에 적은 원칙("파라미터는 모델 노브가 아니라 물려받은 상수를 스윕한다")도
이번 결과로 보강된다. `MLP_ALPHA`는 노브가 아니라 **두 예측기의 상대 신뢰도**를 정하는
구조 상수였고, 그래서 스윕이 통했다.

### 7-5. 방법론적 교훈

1. **양쪽을 걸친 설계가 정답을 살렸다.** 원래 계획은 0.40 아래 3점(0.25/0.30/0.40)이었다.
   그대로 갔으면 "0.40이 최선"으로 끝나고 **+7점을 놓쳤을 것**이다.
   두 이론이 반대를 가리킬 때는 반드시 양쪽을 재야 한다.
2. **Public이 테스트 100%라는 사실이 실험 설계를 바꾼다.** 표본 노이즈가 없어
   0.0001점 차이도 실측이다. 그래서 재현 검증(§5-1 A)이 가능했고, 2차 차분이
   소수 넷째 자리까지 일정한 것도 확인할 수 있었다.
3. **곡선의 형태에 이론적 근거가 있으면 외삽할 수 있다.** Brier가 2차 손실이라는
   구조에서 나온 형태이므로, 5점으로 측정 범위 밖의 꼭짓점을 지목할 수 있었다.
4. **후보를 세울 때 홀드아웃 표만 보면 방향을 틀린다.** DIRECTION.md §6 후보 #1을
   "α 0.40 → 0.30"으로 적었는데 정답은 반대였다. §7.65 표의 숫자만 옮겼고 그 표가
   나온 fold의 성질(f2023 오염 구간, f2024 평평)을 따지지 않은 것이 원인이다.
